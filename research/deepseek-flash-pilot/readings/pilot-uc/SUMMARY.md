## What the pilot can do on this evidence

It can propose task-sensitive routes, emit valid initial child references, generate useful bounded prose/artifact drafts, and read an actual verification result when deciding whether to continue or stop. All eight authoritative current decisions cite the exact latest verification reference (UC1 three, UC2 one, UC3 one, UC4 three). It distinguishes structural checks, critic challenges and unavailable verification in its public reasons. UC1 notices actual camera defects; UC4 correctly notices that the Qwen critic attacks positions its own map already rejected.

These are real capabilities, with a narrow denominator: four task configurations, one current live run each, one pilot model, and one different-lineage verifier call in UC4. Historical attempts1-3 are preserved failed/partial predecessors under changed host amendments, not repeated independent trials of P-A5. No bare/native/matched multi-call control exists here; there is no estimate of general reliability or causal loop advantage.

## Did more loops help?

No completed later-pass artifact improvement is observed. UC1's three additional passes and UC4's two additional passes add diagnosis, source delivery and failure evidence, not an improved script or map. UC1's c0003 same-call repair removes unauthorized source_refs while retaining an identical answer; that is a real delivery correction and not semantic self-correction. UC4's M-to-M-prime table is first-pass composition, not a before/after longitudinal observation.

More loops remain plausible for a concrete, changed task: repair UC1 camera/vector construction; challenge UC2's separation necessity; check UC3's evidence support; complete UC4's already-supplied-source mapping checks. This is a reason to test a valid continuation path, not proof that extra calls outperform a matched alternative. Current stops never exhaust300 calls orUSD 6; UC1 is a host input-window error and UC4's own claimed evidence blocker is partly false.

## One next change

Replace free-form reconstruction of spawn/plan input objects with a **host-validated menu of executable repair actions**, selected by ID. Unlike P-A5's reference menu, each offered action must already satisfy template prerequisites, sealed authority and the task-input/source-read distinction; failure evidence stays addressable by compact references. This is one control-interface change, proposed only. It does not authorize new source, expand budgets, or declare a correct solution.

Question: **Can Flash turn a verify-identified defect into an accepted revised artifact when the offered continuation actions already have valid template inputs and source bindings?**

The question is reopened by an authorized successor with that declared change and a fixed defect-bearing artifact, not by replaying these run paths. Any advantage claim still needs matched information/resource controls. Observed envelope/context/interpretation problems concern L7/L15/L20/L43/L47/L49. L19/L50 remain applicable interface warnings. L21's byte-bound refusal and L53's explicit decision/budget contract functioned as safeguards, without establishing semantic adequacy; further safeguards and claim limits are L22/L31/L40/L41/L44/L45/L46/L48 in the [register](../../../../docs/lessons/harness-lessons-2026-09.md).
