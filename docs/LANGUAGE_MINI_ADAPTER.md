# Language probe adapter and calibration record

The implementation is `src/minireason/language_mini.py`. It builds and runs Mini's actual manifest, stage, port, window, artifact and replay machinery. The completed route is express, reinterpret, criticize, with three model calls per cycle and no automatic retries. Additional cycles repeat the frozen probe; they do not install a language amendment or feed earlier criticism back into the corpus.

The original packet, selected language meaning and optional compiler observation are exact UTF-8 source files. Deterministic Mini machine seats copy each nonempty source into a distinct artifact kind at the start of each cycle. Their duplicated body and commitments fields are transport only. They call no model, reserve no model tokens and appraise no content. Expression and criticism read the full packet artifact; reinterpretation declares only the selected language meaning and current expression artifacts. Criticism also reads the independent reading and any optional compiler artifact. All these ports use `list_bodies` with `this_cycle` windows. Mini's problem field contains a short procedural label, and no model stage reads it. The correct label is source-text-withheld: the source-conditioned language and the expression can themselves contain source information. A prose escape remains legitimate; reconstructing its quotation does not show that the selected formal carrier expressed the distinction.

Before sending a call, the adapter validates Mini's entire actual brief against the declared instruction, exact source-artifact or previous prose bytes, and expected artifact framing. Only the artifact identifiers are treated as variable framing. Missing, changed or additionally exposed material causes `PROBE_ROUTING_MISMATCH` before provider dispatch. The failed routed brief is retained as well. After successful validation, the adapter uses the same `language_study.stage_prompt` function and `language_data.RAW_SYSTEM` as the direct comparator. Internal Mini framing is therefore recorded but does not change the model's conditional request policy. Given identical prior replies and settings, matched and Mini arms send identical messages. This comparison calibrates routing and recording under those controls; differences in ordinary runs can still arise from model sampling. It is not a comparison of two different reasoning prompts.

The model returns raw ordinary text, with optional formal expressions or fenced code. It is never required to emit a Mini JSON envelope. The host preserves that text without semantic parsing. Mini's existing runner nevertheless requires nonempty `body` and `commitments` fields. The adapter therefore places the identical raw text in both fields, while all downstream ports render body alone. This duplication is transport adaptation, not an independent commitment extraction, a second model response, or evidence that body and commitments have been separately appraised. Content-level conjectures, commitments and criticisms remain whatever the original prose says.

Each history row carries the SHA-256 of the original UTF-8 answer. Provider token usage counts what the model generated. The host's JSON envelope and duplicate field are recorded separately as raw and wrapped UTF-8 byte counts. No wrapper token count is estimated: those bytes were not generated by the model or sent back through these body-only ports. Request records retain the original Mini brief, transformed provider prompt and their separate hashes.

No Lean compilation result, formal expression schema, correct answer, or semantic adequacy condition gates this route. Transport and routing failures are operational signals. An unresolved prose objection, an incomplete language and noncompiling code remain artifacts when the provider returned a completed nonempty response. The episode has no automatic adequacy or creativity verdict.

## Exact material preparation

`prepare_probe(root, **material_arguments)` writes the manifest and source files, registers the fixed source-copy handlers, and compiles a `RunPlan` without constructing a provider. It returns a `PreparedProbe`. Its `summary()` records the material digest, raw manifest SHA-256, compiled plan identity, header digest and each source's path, UTF-8 hash, bytes and character count. The experiment runner performs this preflight before constructing any arm provider or starting concurrent work. A malformed configuration ends the comparison with a preflight record and errata, without spending calls in other arms.

`run_probe(..., prepared=prepared)` verifies the incoming frozen material, manifest bytes and compiled source bindings, archives identical sidecars in the arm's own directory, and reuses the compiled plan. No second compilation is needed. Reproduction requires both `manifest.json` and its `sources/` files; `material-bindings.json` records their identities. File writes preserve exact bytes and refuse to overwrite existing outputs.

The source-copy handler resolves a fixed source ID from its current stage's kind and reads that source from its own `context.plan.sources`. It does not capture a mutable global packet. Handler registration is idempotent under a lock, and a conflicting registered implementation is refused. Thus multiple prepared plans can run concurrently without sharing their material. Mini supplies machine seats with the full record; these handlers are trusted deterministic copying code, not a sandbox restricting arbitrary machine functions.

The repair addresses two distinct schema boundaries: Mini's `problem` field allows at most 8,192 characters and a kind's `instruction` allows at most 4,000. Frozen study material belongs in full source files, not in either short field. `sources[].path` loads the complete file and binds its byte hash. No truncation, summary or character-budget substitution is applied. Provider context limits remain separate operational limits; successful Mini compilation is not a promise that every arbitrarily large prompt fits a model.

Eleven focused offline tests cover request parity, source-port exclusion and restoration, exact prose preservation, cycle isolation, partial-run retention, declared content identity, completion-ceiling mismatch, actual renderer leakage, real material beyond inline schema limits, prepared-plan reuse and independent concurrent material routes. These tests use supplied prose fixtures and make no live model calls. They calibrate the instrument; they are not creativity findings.
