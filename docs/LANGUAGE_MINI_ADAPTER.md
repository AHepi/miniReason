# Language probe adapter and calibration record

The implementation is `src/minireason/language_mini.py`. It builds and runs Mini's actual manifest, stage, port, window, artifact and replay machinery. The completed route is express, reinterpret, criticize, with three model calls per cycle and no automatic retries. Additional cycles repeat the frozen probe; they do not install a language amendment or feed earlier criticism back into the corpus.

The original packet is Mini's problem port. Expression and criticism read it; reinterpretation declares only the current expression port and the selected language's proposed meaning. Criticism also reads the independent reading. Optional compiler observations reach criticism only. The correct label is source-text-withheld: the source-conditioned language and the expression can themselves contain source information. A prose escape remains legitimate; reconstructing its quotation does not show that the selected formal carrier expressed the distinction.

Before sending a call, the adapter validates Mini's entire actual brief against the declared instruction, exact packet or previous prose bytes, and expected artifact framing. Only the artifact identifiers are treated as variable framing. Missing, changed or additionally exposed material causes `PROBE_ROUTING_MISMATCH` before provider dispatch. The failed routed brief is retained as well. After successful validation, the adapter uses the same `language_study.stage_prompt` function and `language_data.RAW_SYSTEM` as the direct comparator. Internal Mini framing is therefore recorded but does not change the model's conditional request policy. Given identical prior replies and settings, matched and Mini arms send identical messages. This comparison calibrates routing and recording under those controls; differences in ordinary runs can still arise from model sampling. It is not a comparison of two different reasoning prompts.

The model returns raw ordinary text, with optional formal expressions or fenced code. It is never required to emit a Mini JSON envelope. The host preserves that text without semantic parsing. Mini's existing runner nevertheless requires nonempty `body` and `commitments` fields. The adapter therefore places the identical raw text in both fields, while all downstream ports render body alone. This duplication is transport adaptation, not an independent commitment extraction, a second model response, or evidence that body and commitments have been separately appraised. Content-level conjectures, commitments and criticisms remain whatever the original prose says.

Each history row carries the SHA-256 of the original UTF-8 answer. Provider token usage counts what the model generated. The host's JSON envelope and duplicate field are recorded separately as raw and wrapped UTF-8 byte counts. No wrapper token count is estimated: those bytes were not generated by the model or sent back through these body-only ports. Request records retain the original Mini brief, transformed provider prompt and their separate hashes.

No Lean compilation result, formal expression schema, correct answer, or semantic adequacy condition gates this route. Transport and routing failures are operational signals. An unresolved prose objection, an incomplete language and noncompiling code remain artifacts when the provider returned a completed nonempty response. The episode has no automatic adequacy or creativity verdict.

## Offline calibration errata

| Calibration issue | Cause | Repair or disposition | Evidence |
|---|---|---|---|
| Initial raw-prose wrapping stopped at the first stage | Mini's runner imposes a nonempty-commitments condition beyond its JSON parser; an empty transport placeholder was refused | Store the unchanged prose identically in both transport fields and render only body | `tests/test_language_mini.py` preserves unresolved, noncompiling prose byte for byte |
| An initial outcome assertion compared tuple and list containers | Python dataclass output retained a tuple while the JSON-facing expectation used a list | Normalize the returned stage sequence to a list for consistency with persisted JSON | Completed route and cycle assertions |
| Source packet deliberately injected into a reader brief | Controlled mutation of Mini's actual renderer tested the visibility guard | Refused before the reader provider call; first expression and failed routed brief retained | `test_actual_mini_routing_leak_fails_before_the_reader_call` |
| Reader delivery deliberately failed | Controlled provider fixture withheld the intended observation | Partial expression, operational error and terminal probe record retained; no semantic failure inferred | `test_reader_transport_failure_retains_expression_and_loud_terminal_record` |

Seven focused offline tests cover request parity, source-port exclusion and restoration, exact prose preservation, cycle isolation, partial-run retention, declared content identity, completion-ceiling mismatch and actual renderer leakage. These tests use supplied prose fixtures and make no live model calls. They calibrate the instrument; they are not creativity findings.
