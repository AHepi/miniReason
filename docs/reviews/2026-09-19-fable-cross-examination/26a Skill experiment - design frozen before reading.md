# 26a Skill experiment — design, frozen before reading any reply

What this file is: section 0 of the planned file 26, written at 13:34 UTC on 2026-09-19 after the runs were launched and before any reply was opened, and published on its own so that the design and predictions cannot be edited after the results are seen. File 26 will carry the results and the comparison.

## 0. Design, frozen before reading any reply

**Control.** The plain run of 2026-09-19 10:38 UTC: system prompt "hostile, meticulous referee" (the text is in `witness-replies/cross_examine.py`), battery R1–R9 on file 20, deepseek-flash three samples per item at its 131,072-token cap, Atria-Dawn-Preview one sample per item at its 65,536-token cap, streamed. Adjudicated in file 21: 27 defect groups ruled Valid (1.1–1.27), a small table of Invalid or Partly valid findings, and a sixteen-item revision list.

**Treatment.** Same battery, same document, same models, same caps, same temperature (0.7), same sample counts. The only change is the system prompt: a short framing paragraph (`witness-replies/frame_htv.txt`, `frame_sc.txt`) followed by the skill's SKILL.md and every file in its `references/` folder, verbatim (`witness-replies/method-skills/`). The framing tells the witness to take the item prompt as the frozen question (hard-to-vary) or as the writer's own diagnosis to be checked first (story-critique), to run the skill's whole procedure, and to report in the skill's own format. System prompt sizes: hard-to-vary 55,593 characters; story-critique 48,261 characters; the plain prompt was 1,013 characters.

**What is measured, in this order.**
1. *Incapacitation.* Empty replies, cut streams, replies that abandon the document for the skill (talk about the method rather than the text), replies that break the numbered-finding rule, and reply length and time against the control.
2. *Structure adherence.* Whether the reply actually carries the skill's report: for hard-to-vary, a frozen question, parts, per-part marks (held / loose / idle / borrowed / unknown), whole-explanation checks, provenance of parts (fitted / built / asserted), one next step; for story-critique, corrections first, scene notes with the four steps, the fit paragraph, the ranked two or three faults, what I am unsure of, one next step.
3. *Recall of known defects.* For each of file 21's 27 Valid groups, whether any reply in the treatment finds it. A keyword probe (`witness-replies/score_replies.py`) makes the first pass; every hit and miss is confirmed by reading.
4. *New findings.* Anything a treatment reply says about file 20 that file 21 does not contain, ruled Valid, Partly valid or Invalid against file 20's text, exactly as in file 21.
5. *False findings.* Claims about the text that the text contradicts, counted per witness and per method.
6. *Kind of finding.* Whether the skill shifts findings from "this sentence is wrong" (local) toward "this part is loose / this part does no job" (structural), and whether those structural findings match the six structural survivors named in file 25.

**What this cannot show.** One run per method per model, at temperature 0.7, against one control run. A difference of two or three defects in either direction is inside run-to-run variation (file 21 §0: the three DeepSeek samples of one item overlap only partly). Only a difference that shows in *both* witnesses, or a change in kind rather than count, will be read as a method effect. The hard-to-vary skill was built from file 10's terms, so a witness using it against file 20 is applying the theory's own test to a revision of the theory; where a reply's finding rests on the skill's word list rather than on file 20, it is marked as such and not counted.

**Predictions written before reading, so that they can be wrong.** (a) Neither skill will empty more replies than the control (the caps are the binding constraint, not the prompt). (b) Hard-to-vary will lower the raw count of findings and raise the share that are structural; it will recover the identity/modular-lookup point (1.5) and the provenance-through-the-tuple point more often, because "swap" and "where did this part come from" are its native moves, and it will find fewer typing slips (1.16–1.19) because it does not read clause by clause. (c) Story-critique will produce the fewest defects and the most text about the method's own limits, and its useful output, if any, will be about the document's *order of exposition* (planted and never collected, the chain of questions), which no earlier round attacked. (d) Atria will follow the report format more closely than DeepSeek, from the pattern in files 18 and 19.
