## Findings

1. **Selection witness is trivially satisfiable by cherry-picking \(H\) and using an irrelevant \(\mu\).**  
   **Claim attacked:** “a finite history \(H\subseteq C_t\) … non-empty; a variation operator \(\mu\) … that was applied at least once … and produced a member that differs from its parent at some pair of \(H\); … eliminated at least one member that differed from \(t\) at a pair of \(H\) on which that member failed and \(t\) did not.”  
   **Why it fails:** Nothing requires \(t\) to descend from \(\mu\), nothing requires the eliminated rival to be produced by \(\mu\), and nothing requires \(H\) to be the entire encountered history or to be fixed before survival. If \(t\) is faithful on one pair, and a broken rival fails on that pair, then \(|T|\ge 2\), non-empty \(H\), an applied variation, and an elimination are all satisfied. This is not the excluded trivial reading (singleton population, empty history).  
   **Severity:** Fatal.  
   **Fix:** Require \(t\)’s lineage to be produced by \(\mu\); require the eliminated rival to be produced by \(\mu\) or to be in the same lineage; require \(H\) to be the set of all encountered pairs in \(\Sigma_h\), fixed before survival.

2. **The survival condition is circular: it is defined as fidelity on \(H\).**  
   **Claim attacked:** “a survival condition that holds of a member exactly when it is faithful on \(H\) (fidelity on \(H\) is necessary and sufficient for survival).”  
   **Why it fails:** Survival is a physical/environmental event, but here it is defined by the semantics’ own fidelity predicate. The difference-making condition — the rival failed where \(t\) did not — is then tautological. Selection is assumed to discriminate on fidelity rather than shown to do so.  
   **Severity:** Fatal.  
   **Fix:** The physical module must supply a survival predicate independently of fidelity. \(H\) is then the set of changes on which survival actually depended; the difference-making condition is derived, not stipulated.

3. **Blindness is mis-scoped: it constrains only the route to \(\mu\), not the route to survival.**  
   **Claim attacked:** “no itemised representation of a defect … lies on any active route from a failure to an application of \(\mu\).”  
   **Why it fails:** An itemised defect record used to eliminate failures lies on the route from failure to survival, not necessarily to \(\mu\). A process can therefore use itemised error records to cull members and still satisfy the blindness clause. If \(\mu\) is applied before any failure, the clause is vacuous outright. “Blind” selection can be fully sighted selection.  
   **Severity:** Fatal.  
   **Fix:** Forbid itemised defect representations on any active route from failure to variation *or* to survival. Require \(\mu\) to be applied after the failure that affects survival.

4. **The aggregate-summary exemption is not well-defined.**  
   **Claim attacked:** “an *aggregate* summary — a function of the multiset of failures invariant under permuting which record failed, such as how many and how badly — is explicitly permitted.”  
   **Why it fails:** Any function of a multiset is already invariant under permutations of the underlying records. The identity function on the multiset of (failed state, what-would-have-held) pairs satisfies the stated condition and is fully itemising. The exemption gives no coarsening or loss requirement.  
   **Severity:** Serious.  
   **Fix:** Define an aggregate as a statistic that destroys the pairing between failed state and counterfactual — e.g. cardinality or severity distribution — and explicitly forbid any summary from which the multiset can be recovered.

5. **The itemised-defect definition is too narrow.**  
   **Claim attacked:** “an occurrence instantiating a record that pairs the state at which fidelity failed with what would have held.”  
   **Why it fails:** A system can store the failed state and the counterfactual in separate components, in a distributed code, as a correction rather than a counterfactual, or in a format from which both are recoverable. None of these is an occurrence instantiating a single record pairing the two. A sighted system can escape the definition.  
   **Severity:** Serious.  
   **Fix:** Define defect representation functionally: any representation from which the failed state and a target/correction can be recovered and which is used in the relevant route.

6. **The blindness/defect-record pair is not a separator.**  
   **Claim attacked:** “What keeps the two apart is one thing, and it is in both definitions: a selection witness is blind … and a construction witness requires one on the route to the binding. … A process that is blind is not constructing; a process with the defect record on its route is not selecting, whatever else it does.”  
   **Why it fails:** Blindness forbids an itemised defect on the route from failure to \(\mu\). Construction requires an itemised defect on the route to the binding. These are different routes. A process can have an itemised defect record on the binding route and no itemised defect on the \(\mu\) route. Both \( \operatorname{Sel} \) and \( \operatorname{Con} \) can then hold. The universal claim about “a process” is false for any process with disjoint subhistories.  
   **Severity:** Fatal.  
   **Fix:** Make the predicates mutually exclusive on the same transport/route, e.g. \(\operatorname{Sel}(t)\) requires no construction witness for \(t\), and \(\operatorname{Con}(t)\) requires no selection witness for \(t\); or replace the pair with a single provenance predicate over structured aspects.

7. **Construction is gerrymanderable: the defect record need not be relevant to the binding.**  
   **Claim attacked:** Build “contains an itemised defect representation — an occurrence instantiating a record pairing a state at which some prior transport of \(s\) failed fidelity with what would have held — on an active route to the binding.”  
   **Why it fails:** “Some prior transport” need not be the transport the binding corrects. A generic error signal that triggers a random new component binding satisfies the clause. The active route only requires causal connectedness, not that the record’s content is used to determine the binding.  
   **Severity:** Serious.  
   **Fix:** Require the defect record to represent the failure that the binding corrects; require the binding’s content to counterfactually depend on the record; require improved fidelity relative to that failure.

8. **Non-triviality is ill-typed.**  
   **Claim attacked:** “no event of \(\Sigma_h\) instantiates an organization held to \(t\), to \(H\), or to the survival condition by a faithful transport.”  
   **Why it fails:** \(t\) is a transport, \(H\) is a set of edit–boundary pairs, and a survival condition is a predicate. “Held to” is defined for organizations and contents. \(H\) and the survival condition are not organizations in this semantics. The clause has no well-formed target for “an organization held to \(H\)” or “held to the survival condition.”  
   **Severity:** Serious.  
   **Fix:** Define organizations that represent the selection data, or restrict non-triviality to representations of \(t\)’s contract and the selection predicates.

9. **Non-triviality is either too weak or too strong regarding designers/experimenters.**  
   **Claim attacked:** “no event of \(\Sigma_h\) instantiates an organization held to \(t\), to \(H\), or to the survival condition by a faithful transport.”  
   **Why it fails:** A designer or experimenter outside \(\Sigma_h\) can represent \(t\), \(H\), and the survival condition and set up the filter, while no event in \(\Sigma_h\) represents them. The clause permits artificial selection. If the designer is inside \(\Sigma_h\), then any selection process that represents its own criteria fails, which excludes legitimate artificial selection and even some natural cases.  
   **Severity:** Serious.  
   **Fix:** Either allow environmental/designer representation of selection criteria, or define non-triviality relative to a specified system boundary and make the boundary explicit.

10. **The population clause is a type error.**  
    **Claim attacked:** “a population \(\mathcal T\) of realized organization–transport pairs, each instantiated by an occurrence under \(\Theta\).”  
    **Why it fails:** \(\Theta\) supplies \(\operatorname{Inst}\) for organizations, not transports. A transport is a mathematical tuple \((\pi,\tau,\sigma,\lambda)\). There is no definition of what it is for a transport to be “realized” or for an occurrence to instantiate a transport. The variation operator \(\mu\) then acts on these mathematical objects, but \(\mu\) is also required to be physically admitted.  
    **Severity:** Serious.  
    **Fix:** Define the population as occurrences instantiating organizations; define transports as derived from those organizations; define \(\mu\) as a physical process altering occurrences, not transports.

11. **No common descent, reproduction, or heritability is required.**  
    **Claim attacked:** “a population \(\mathcal T\) of realized organization–transport pairs.”  
    **Why it fails:** Two unrelated systems suffice. There is no requirement that the members share an ancestor, that variation is heritable, or that survival affects reproduction. This is not selection in any standard sense; it is a filter over a set.  
    **Severity:** Serious.  
    **Fix:** Require common descent, heritability of the varied organization/transport, and reproduction or retention across generations.

12. **\(H\) can be cherry-picked.**  
    **Claim attacked:** “a finite history \(H\subseteq C_t\) … each pair occurring as an event of \(\Sigma_h\), non-empty.”  
    **Why it fails:** \(H\) need not be all encountered changes. The witness can select a single pair on which \(t\) is faithful and a rival fails. The exclusions of singleton population and empty history do not exclude a two-member population and a one-pair \(H\).  
    **Severity:** Fatal.  
    **Fix:** Require \(H\) to be the entire set of encountered pairs in \(\Sigma_h\), or at least fixed independently of \(t\)’s survival.

13. **The survival condition is ill-defined for members other than \(t\).**  
    **Claim attacked:** “a survival condition that holds of a member exactly when it is faithful on \(H\).”  
    **Why it fails:** \(H\subseteq C_t\), the contract of \(t\)’s content. Other members have their own organizations, transports, and contracts. Fidelity on \(H\) for a rival is not defined unless \(H\) is translated into the rival’s contract and the relevant anchor map is specified.  
    **Severity:** Serious.  
    **Fix:** Define a common target and contract for the population, or define survival for each member relative to its own contract and a common set of encountered changes.

14. **The earliest-witness rule fails when witnesses are incomparable.**  
    **Claim attacked:** “the provenance of the earliest witness in \(\prec_h\) whose events produced the occurrence that carries \(t\).”  
    **Why it fails:** \(\prec_h\) is an acyclic precedence order, not necessarily total. Two witnesses may both produce the occurrence and be incomparable. Then there is no “earliest” witness.  
    **Severity:** Serious.  
    **Fix:** Require a unique minimal witness, or define provenance as a set/structured object when incomparable witnesses exist.

15. **The earliest-witness rule misclassifies later constitutive construction as maintenance.**  
    **Claim attacked:** “Later histories are maintenance and do not change provenance.”  
    **Why it fails:** A later construction episode can change the binding \(\lambda(k)\) and therefore change the transport itself. That is not maintenance. If selection occurred earlier, the rule assigns the modified transport selected provenance, even though its current binding was constructed.  
    **Severity:** Serious.  
    **Fix:** Define provenance from the last constitutive event, or as a structured set of contributions; require later construction to produce a new transport token if it is to have constructed provenance.

16. **The production relation in the earliest-witness rule is undefined.**  
    **Claim attacked:** “whose events produced the occurrence that carries \(t\).”  
    **Why it fails:** The physical module supplies \(\operatorname{Inst}\), \(\prec\), and \(\operatorname{Exec}\), but not a relation “event \(e\) produced occurrence \(o\).” The rule relies on an undefined causal-production relation.  
    **Severity:** Serious.  
    **Fix:** Define production via the process-dependency order or a specified causal ancestry relation in the physical module.

17. **Construction can be rewritten as selection under the stated definitions.**  
    **Claim attacked:** “A demonstration that every construction witness … can be rewritten as a selection witness satisfying the elimination and blindness clauses of Part IV, without loss.”  
    **Why it fails:** Let \(t\) be any constructed transport. Choose a pair \((a,b)\) in \(t\)’s contract where \(t\) is faithful. Realize a rival \(r\) that fails at \((a,b)\). Let \(T=\{t,r\}\). Let \(\mu\) be a physically admitted mutation applied to \(r\), producing \(r'\) that still fails at \((a,b)\). Let survival be fidelity on \(H=\{(a,b)\}\). Then \(|T|\ge 2\), \(H\) is non-empty, \(\mu\) was applied, \(r'\) differs from its parent at a pair of \(H\), and \(r'\) is eliminated while \(t\) survives. Blindness holds if no itemised defect record lies on the route from \(r'\)’s failure to \(\mu\); the construction’s defect record can lie on the binding route instead. This satisfies the stated non-trivial reading, not the excluded singleton/empty reading. Thus every constructed transport with a realizable rival is also selected.  
    **Severity:** Fatal.  
    **Fix:** Require \(t\) to be produced by \(\mu\); require the eliminated rival to be in \(t\)’s lineage; require \(H\) not to be cherry-picked; make \(\operatorname{Sel}(t)\) and \(\operatorname{Con}(t)\) mutually exclusive.

18. **Selection and construction can overlap.**  
    **Claim attacked:** “Construction is not selection.”  
    **Why it fails:** A selection process can contain an itemised defect record on the route to a binding while remaining blind with respect to \(\mu\) and survival. If the other Build conditions hold, \(\operatorname{Con}\) also holds. The predicates are not exclusive because they constrain different routes.  
    **Severity:** Serious.  
    **Fix:** Define the predicates so that a transport cannot satisfy both, or replace them with a single provenance predicate with explicit aspects.

19. **The claim that blindness/defect-record is the “only” separator is false.**  
    **Claim attacked:** “What keeps the two apart is one thing.”  
    **Why it fails:** Selection additionally requires a population, a variation operator, a survival condition, and an elimination. Construction additionally requires an owned subhistory, a nontrivial binding, and not being a composition of content-preserving transfers. These are further differences. The “one thing” formulation is inaccurate even before the separator fails.  
    **Severity:** Minor to serious.  
    **Fix:** State all differences explicitly and stop claiming a single separator.

20. **One process can satisfy both witnesses.**  
    **Claim attacked:** “A process that is blind is not constructing; a process with the defect record on its route is not selecting, whatever else it does.”  
    **Why it fails:** A process can have a blind selection subhistory for one transport and a construction subhistory for another, or even for the same carrier if the routes are disjoint. The definitions are route-local; the process-level universal claim is false.  
    **Severity:** Fatal.  
    **Fix:** Define selection and construction at the level of a specific transport/route, not at the level of a whole process; or require a single provenance assignment for the process and make it exclusive.

21. **Blindness only checks the current active route, not the causal history.**  
    **Claim attacked:** “no itemised representation of a defect … lies on any active route from a failure to an application of \(\mu\).”  
    **Why it fails:** A system can compute an aggregate from itemised defect records and discard the records before \(\mu\). The itemised records are in the causal history of the aggregate, but they do not lie on the current active route. The process is classified blind although it was sighted upstream.  
    **Severity:** Serious.  
    **Fix:** Forbid itemised defect representations anywhere in the causal history of the variation, not only on the current active route.

**1. The survival condition is circular and stipulative, not a physical selection condition.**
- **Attacked claim:** “a survival condition that holds of a member exactly when it is faithful on \(H\) (fidelity on \(H\) is necessary and sufficient for survival)”.
- **Why it fails:** This defines survival as fidelity on the very history \(H\) that the selection witness is supposed to test. Any transport \(t\) that is faithful on some nonempty \(H\) can be placed in a population with a rival that differs on \(H\); the rival is eliminated by definition. Selection no longer reports an independently specified environmental filter; it reports that the model-builder chose \(H\) and defined survival to match it.
- **Severity:** fatal.
- **Fix:** Require the survival condition to be specified independently of \(H\) and of the candidate, e.g. environmental task performance; fidelity on \(H\) must be a consequence of survival, not its definition.

**2. \(H\) can be chosen post hoc and need not be the encountered history in any causally relevant order.**
- **Attacked claim:** “a finite history \(H\subseteq C_t\) of edit–boundary pairs, where \(C_t\) is the contract of \(t\)'s content, each pair occurring as an event of \(\Sigma_h\), non-empty”.
- **Why it fails:** The definition does not require \(H\) to be fixed before the selection event, nor to be the whole encountered history, nor to be the history against which survival actually acted. One can choose \(H\) as a subset on which \(t\) happens to be faithful and on which a rival happens to fail. That is gerrymandering.
- **Severity:** serious.
- **Fix:** Require \(H\) to be the actual encountered change history, fixed independently of the survivor and recorded before the survival outcome is used.

**3. \(t\) need not be produced by the variation operator \(\mu\).**
- **Attacked claim:** “a variation operator \(\mu\) on \(\mathcal T\), physically admitted, that was applied at least once in the selection history \(\Sigma_h\) and produced a member that differs from its parent at some pair of \(H\)” and “\(t\) is a member that survived”.
- **Why it fails:** The definition never says that \(t\) or its lineage is the product of \(\mu\). A pre-existing \(t\) can sit in a population while \(\mu\) mutates some other member and the survival condition eliminates some unrelated rival. \(t\) then counts as selected even though selection did not produce it.
- **Severity:** fatal.
- **Fix:** Require \(t\)'s occurrence or lineage to be produced by \(\mu\) in \(\Sigma_h\), or to descend from a \(\mu\)-produced member, with a causal route from that variation to \(t\).

**4. The eliminated rival need not be produced by \(\mu\), and the difference-making clause is largely redundant.**
- **Attacked claim:** “which **eliminated at least one member** that differed from \(t\) at a pair of \(H\) on which that member failed and \(t\) did not”.
- **Why it fails:** The eliminated rival is not required to be generated by \(\mu\), nor to be the member \(\mu\) produced. Worse, since survival is defined as fidelity on \(H\), if \(t\) is faithful on \(H\), then any rival that differs from \(t\) at a pair in \(H\) automatically fails at that pair. The clause adds almost no constraint beyond “some eliminated rival differs on \(H\).”
- **Severity:** serious.
- **Fix:** Require the eliminated rival to be \(\mu\)-generated, require its elimination to be due to the specific failure at the differentiating pair, and make the survival condition independent enough that this is not automatic.

**5. The population need not share a common target or contract, so “faithful on \(H\)” may be ill-typed for other members.**
- **Attacked claim:** “a population \(\mathcal T\) of realized organization–transport pairs” and “a survival condition that holds of a member exactly when it is faithful on \(H\)”.
- **Why it fails:** \(H\subseteq C_t\), the contract of \(t\)'s content. Other population members may have different contents, different contracts, and translations undefined on \(H\). The definition does not require a common target, common content, or common contract, so fidelity on \(H\) for other members is undefined or incomparable.
- **Severity:** serious/fatal.
- **Fix:** Require all members to share the same target/content contract, or define \(H\) per member with a common target and common translation.

**6. Non-triviality is ill-typed.**
- **Attacked claim:** “**Non-triviality:** no event of \(\Sigma_h\) instantiates an organization held to \(t\), to \(H\), or to the survival condition by a faithful transport.”
- **Why it fails:** \(H\) is a set of edit–boundary pairs; the survival condition is a predicate. Neither is obviously an organization or a content that can be “held to” by a transport. “Held to \(t\)” is also obscure: \(t\) is itself a transport, though Part X later allows transports as contents. As written, the condition is either vacuous, impossible, or dependent on an unstated representation relation.
- **Severity:** serious.
- **Fix:** State exactly what organizations/contents represent \(t\), \(H\), and the survival condition, and use the already-defined \(\operatorname{Rep}\) or an explicitly different relation.

**7. Non-triviality does not forbid a faithful representation of the target or of correct answers on \(H\).**
- **Attacked claim:** “no event of \(\Sigma_h\) instantiates an organization held to \(t\), to \(H\), or to the survival condition by a faithful transport”.
- **Why it fails:** The condition forbids representing \(t\), \(H\), and the survival condition, but not the target \(D\), its answer profile, or the correct component relations on \(H\). A system can carry an itemised faithful transport of the target’s behavior on \(H\) and use it to guide variation while satisfying non-triviality as written.
- **Severity:** fatal to the claim that selection is blind.
- **Fix:** Forbid any faithful transport of the target’s answer profile on \(H\), or of any criterion that determines survival on \(H\), on any active route to \(\mu\).

**8. Blindness forbids itemised defect records, but not itemised correct behavior.**
- **Attacked claim:** “**Blindness:** no itemised representation of a defect — an occurrence instantiating a record that pairs the state at which fidelity failed with what would have held — lies on any active route from a failure to an application of \(\mu\)”.
- **Why it fails:** A lookup table of correct target behavior is not a “defect record” unless it is paired with a prior failure. It can nevertheless guide \(\mu\) to the correct relation directly. The definition of blindness leaves this route open.
- **Severity:** serious/fatal.
- **Fix:** Extend blindness to any itemised representation of the target’s behavior, answer, or survival criterion on the route to \(\mu\).

**9. The aggregate-summary exemption is not well-defined and swallows blindness.**
- **Attacked claim:** “an *aggregate* summary — a function of the multiset of failures invariant under permuting which record failed, such as how many and how badly — is explicitly permitted and does not make the process sighted.”
- **Why it fails:** Any function of a multiset is invariant under permuting the labels of its elements; that clause imposes no restriction. The identity function on the multiset of failures is a “function of the multiset” and returns the full itemised records. With a singleton failure, any function, including the exact record, is trivially permutation-invariant. So the exemption permits exactly what blindness forbids.
- **Severity:** fatal.
- **Fix:** Define admissible aggregates as functions factoring through a declared coarse statistic that provably erases the state–correct-value pairing, and explicitly forbid identity, injective, or invertible summaries.

**10. “How badly” leaks target information.**
- **Attacked claim:** “such as how many and how badly”.
- **Why it fails:** To compute “how badly” a transport failed, the system generally needs the correct value or target answer at that state. That is itemised target information, even if aggregated over failures.
- **Severity:** serious.
- **Fix:** Specify the metric for severity and either forbid access to target values or prove that the aggregate cannot be inverted to recover them.

**11. \(\mu\) can encode the target even without a defect record.**
- **Attacked claim:** “a variation operator \(\mu\) on \(\mathcal T\), physically admitted”.
- **Why it fails:** “Physically admitted” does not exclude a mutation operator hardwired to set the relation at pairs in \(H\) to the correct value. Non-triviality does not obviously forbid this, because the operator’s input–output map is not itself an event instantiating an organization held to \(t\), \(H\), or the survival condition.
- **Severity:** fatal to the blind-selection claim.
- **Fix:** Require \(\mu\) to be blind to the target’s answer on \(H\), or extend non-triviality to cover the operator’s implemented input–output relation.

**12. “Parent” is undefined.**
- **Attacked claim:** “produced a member that differs from its parent at some pair of \(H\)”.
- **Why it fails:** \(\mathcal T\) is described as a set of realized organization–transport pairs. A set has no parent relation. Without a genealogical tree or a defined ancestry relation, “parent” is undefined.
- **Severity:** serious/minor.
- **Fix:** Define the population as a genealogical structure with a parent/descent relation over the selection history.

**13. Blindness/defect-record is not the only separator.**
- **Attacked claim:** “What keeps the two apart is one thing, and it is in both definitions”.
- **Why it fails:** Selection also contains non-triviality, population, variation, survival, and elimination clauses. Construction also contains owned subhistory, prepares a faithful organization, nontrivial binding required, not a composition of content-preserving transfers, and more. Even if blindness/defect-record were exclusive, these other clauses separate the witnesses.
- **Severity:** serious.
- **Fix:** Say it is one necessary contrast, not the only separator.

**14. The blindness/defect-record pair is not a separator: one process can satisfy both.**
- **Attacked claim:** “A process that is blind is not constructing; a process with the defect record on its route is not selecting, whatever else it does.”
- **Why it fails:** Selection forbids an itemised defect record on an active route from a failure to an application of \(\mu\). Construction requires an itemised defect record on an active route to the binding. These can be disjoint routes in one process. A process can have a blind variation route and, separately, a binding-construction route with an itemised defect record. It then satisfies both definitions. The sentence is false at the process level.
- **Severity:** fatal.
- **Fix:** Define exclusivity at the level of the occurrence/provenance of the transport, not at the level of “the process”, and either forbid the same occurrence from having both witnesses or allow composite provenance explicitly.

**15. Build’s defect record is not required to be causally responsible for the binding.**
- **Attacked claim:** Build “contains an **itemised defect representation** … on an active route to the binding”.
- **Why it fails:** “On an active route” is weaker than “used to construct the binding”. A record can sit on a connected subnetwork and be irrelevant to the binding’s actual construction. The definition supplies no counterfactual: remove or alter the record and the binding need not change.
- **Severity:** fatal.
- **Fix:** Require that removing or replacing the defect record breaks the binding construction, or that the binding fails (F1) or (F2) without the record, under a contrast fixed independently of the candidate.

**16. “Active route to the binding” is ill-typed.**
- **Attacked claim:** “on an active route to the binding”.
- **Why it fails:** An active route is defined in Part IX as a connected subnetwork of actual occurrences joining an occurrence instantiating the input organization to an operative result. A binding is an assignment \(\lambda(k)\) of a component to a subnetwork. An assignment is not an occurrence or an operative result, so a route “to the binding” is not defined by the semantics as written.
- **Severity:** serious.
- **Fix:** Define the binding construction as a process occurrence or an operative result, and define the route to that occurrence/result.

**17. Build’s defect record can be unrelated to the content, question, or binding.**
- **Attacked claim:** “an occurrence instantiating a record pairing a state at which some prior transport of \(s\) failed fidelity with what would have held”.
- **Why it fails:** “Some prior transport” need not be a transport for the same content \(c\), the same target, or the same question. The record need not be about the defect the binding corrects.
- **Severity:** serious.
- **Fix:** Require the prior transport to be for the same target/content/contract, and require the defect record to identify the defect that the binding construction addresses.

**18. The defect record need not be true or faithful.**
- **Attacked claim:** “a record pairing a state at which some prior transport of \(s\) failed fidelity with what would have held”.
- **Why it fails:** The definition does not require “what would have held” to be correct, faithful, or warranted. A bogus record satisfies the syntactic condition.
- **Severity:** serious.
- **Fix:** Require the record’s content to be faithful to the target at that state, or at least require an account of why the correction is correct, with a stated provenance.

**19. “Deleting the binding” makes (F1) undefined, so the requiredness condition is trivial.**
- **Attacked claim:** “it is **required for the transport** when deleting the binding breaks (F1) or (F2) for that transport on \(c\)'s contract.”
- **Why it fails:** A binding is an assignment \(\lambda(k)\). If you delete the assignment, component \(k\) has no anchor, so (F1) cannot be evaluated. That is not “breaking” (F1); it is making the transport ill-formed. Every binding is then “required” in this trivial sense.
- **Severity:** serious/fatal.
- **Fix:** Define deletion as removing the component or replacing its relation by the full relation while keeping the transport well-defined, and require (F1) or (F2) to fail as a result.

**20. Nontrivial binding can be gerrymandered by any new arbitrary component.**
- **Attacked claim:** “a binding construction is **nontrivial** when the binding is neither a relabelling of a binding already in the repertoire nor obtainable from the incoming carriers by \(\equiv_\ell\)”.
- **Why it fails:** Any arbitrary new component with a new anchor can satisfy “not a relabelling” and “not obtainable by \(\equiv_\ell\)”. The definition does not require the binding to solve the recorded defect or to be necessary for the content.
- **Severity:** serious.
- **Fix:** Require the binding to be the construction that corrects the recorded failure and that no prior repertoire element plus content-preserving transfer already supplies.

**21. Build’s “not a composition of content-preserving transfers” is undefined.**
- **Attacked claim:** “and is not a composition of content-preserving transfers.”
- **Why it fails:** “Composition” is not defined for construction histories or transfers. Any construction can be described as not such a composition by adding a nontrivial binding step. Conversely, it is unclear what would count as a relay or composition.
- **Severity:** serious.
- **Fix:** Define composition of transfers, define the closure of content-preserving transfer operations, and require the Build history not to factor through that closure.

**22. Construction can still be rewritten as selection under the current wording.**
- **Attacked claim:** Part IV’s claim that selection is blind and construction has the defect record, so the two are separate.
- **Why it fails:** Selection does not require \(t\) to be produced by \(\mu\). A constructed transport \(t\) can be placed in a population, a blind \(\mu\) can be applied to some other member, a rival can differ on a chosen nonempty \(H\), and survival defined as fidelity on \(H\) eliminates the rival. If the construction’s defect record is on the binding route and not on the failure-to-\(\mu\) route, blindness is untouched. Thus the construction witness can coexist with a selection witness.
- **Severity:** fatal to the separation.
- **Fix:** Require selection to produce the occurrence of \(t\), not merely contain \(t\), and make Sel and Con mutually exclusive for the same occurrence.

**23. Selection can still be rewritten as construction under the current wording.**
- **Attacked claim:** Build requires an itemised defect record on an active route to the binding.
- **Why it fails:** Build does not require the defect record to be causally responsible for the binding, nor the binding to correct that defect, nor the active route contrasts to be fixed independently. A selected transport can be augmented with a record of some prior failure placed on a gerrymandered active route to a trivial binding, satisfying Build as written.
- **Severity:** fatal to the separation.
- **Fix:** Require the defect record to be necessary for the binding, the binding to be necessary for the transport, and the active-route contrasts to be fixed independently of the candidate.

**24. The earliest-witness rule is not well-defined because \(\prec_h\) is not total.**
- **Attacked claim:** “the provenance of the **earliest** witness in \(\prec_h\) whose events produced the occurrence that carries \(t\)”.
- **Why it fails:** \(\prec_h\) is an acyclic precedence order, not a total order. There may be multiple minimal producing witnesses incomparable under \(\prec_h\). Then there is no unique earliest witness and provenance is undefined.
- **Severity:** serious.
- **Fix:** Require a total order on producing witnesses, or define provenance as a set/lattice when no unique minimum exists.

**25. “Whose events produced the occurrence” is undefined and permits mixed provenance to be mislabelled.**
- **Attacked claim:** “whose events produced the occurrence that carries \(t\)”.
- **Why it fails:** If a selected process produced the carrier and a later construction produced the binding, which events “produced the occurrence”? The rule gives no criterion. If the earliest producing event wins, selection may always label a transport built on selected material, defeating construction provenance. If not, the rule is incomplete.
- **Severity:** serious/fatal.
- **Fix:** Define the production relation over occurrences and parts, and either allow composite provenance or define occurrence identity so the constructed transport is a new occurrence.

**26. The earliest-witness rule does not prevent a transport from satisfying both Sel and Con.**
- **Attacked claim:** “the earliest-witness rule says which the resulting transport bears.”
- **Why it fails:** The rule assigns a provenance label. It does not make \(\operatorname{Con}(t)\) false when \(\operatorname{Sel}(t)\) is true, or vice versa. So (R) can still be witnessed by both, and the semantics can report a selected provenance for a transport that also has a construction witness.
- **Severity:** serious.
- **Fix:** Define Sel and Con to be mutually exclusive predicates for the same occurrence, or replace the single-label rule with a provenance lattice and state how (R) uses it.

**27. The earliest-witness rule conflicts with construction on selected material.**
- **Attacked claim:** “Construction may operate on selected material. Selection may continue to operate beneath construction; the earliest-witness rule says which provenance the resulting transport bears.”
- **Why it fails:** If selection is earlier and produced the carrier, the earliest-witness rule can label the resulting transport selected, even though the construction introduced the new binding and did the originative work. That undercuts the claim that construction is a separate creative provenance.
- **Severity:** serious.
- **Fix:** Define provenance per component or per binding, or allow a constructed transport to override an earlier selected carrier when the construction witness is what produces the new transport occurrence.

**28. The active-route contrasts in Build are declared by the candidate, making dependence trivial.**
- **Attacked claim:** Build requires the defect representation “on an active route to the binding”.
- **Why it fails:** Active routes require “nonconstant dependence on the instantiated distinction under the declared contrasts”. Build does not fix those contrasts. A candidate can declare contrasts under which any attached record changes something, making the record “active”.
- **Severity:** serious.
- **Fix:** Fix the contrasts independently of the candidate, or require the exact counterfactual: removing the defect record breaks the binding.

**29. “Itemised defect representation” is ambiguous between a syntactic record and the defined representation predicate.**
- **Attacked claim:** “an **itemised defect representation** — an occurrence instantiating a record pairing a state at which some prior transport of \(s\) failed fidelity with what would have held”.
- **Why it fails:** The gloss defines an occurrence instantiating a record, not a faithful transport with provenance. If “representation” is meant in the sense of (R), Build is circular or understated; if it is not, then it is not a representation in the semantics’ sense, and the word is doing no work.
- **Severity:** serious.
- **Fix:** State which relation is meant. If it is not (R), say so explicitly and define the record’s correctness independently.

**30. The aggregate-summary phrase “invariant under permuting which record failed” is formally incoherent.**
- **Attacked claim:** “invariant under permuting which record failed”.
- **Why it fails:** A multiset is already unordered. Permuting the labels of its elements does not change the multiset. The phrase “which record failed” treats records as labeled elements, but the invariance condition is either vacuous or undefined.
- **Severity:** minor/cosmetic, but it contributes to the exemption being unusable.
- **Fix:** State the permitted statistic extensionally: a declared function of the unlabeled multiset with a proved loss of the state–correct-value pairing.

**Direct answers.**
- **Selection trivial/gerrymanderable?** Yes. Survival is defined as fidelity on \(H\), \(H\) and the rival need not be causally tied to \(\mu\), and \(t\) need not be produced by \(\mu\).
- **Build trivial/gerrymanderable?** Yes. The defect record need not be true, relevant, or causally responsible for the binding; “active route to the binding” is ill-typed; “deleting the binding” makes requiredness trivial.
- **Is blindness/defect-record the only separator?** No. Many other clauses differ.
- **Is it a separator?** No. The routes are different, and one process can have a blind variation route and a defect-record binding route.
- **Aggregate-summary exemption well-defined?** No. It permits the identity function on the multiset, and “how badly” can leak target values.
- **Does the earliest-witness rule work?** No. It assumes a unique earliest producing witness, leaves “produced” undefined, mishandles mixed provenance, and does not make Sel and Con exclusive.
- **Can construction be rewritten as selection or vice versa?** Under the current wording, both directions remain open. Construction can coexist with selection via disjoint routes; selection can be augmented with a gerrymandered defect record on an active route to a trivial binding.

1. **Claim attacked:** “a survival condition that holds of a member exactly when it is faithful on \(H\) (fidelity on \(H\) is necessary and sufficient for survival)”.
   **Why it fails:** This does not describe a selection pressure; it defines survival as a filter that implements fidelity on \(H\). If \(H\) is chosen after observing which members fail, the “survival condition” is gerrymandered to the data. Nothing in the definition requires \(H\) to be fixed before the population or before the survival events.
   **Severity:** fatal for treating `Sel` as a non-trivial physical provenance.
   **Fix:** require \(H\) to be fixed independently of the candidates, or require it to be the encountered history rather than a post hoc subset; add a counterfactual condition that the survival condition was not chosen using knowledge of which members fail.

2. **Claim attacked:** “a finite history \(H\subseteq C_t\) … non-empty”.
   **Why it fails:** Non-emptiness permits \(H=\{(a,b)\}\) for a single pair. Then selection is just “t was faithful at one pair and a rival was not.” That is almost no constraint.
   **Severity:** serious.
   **Fix:** require \(H\) to be representative of the contract in some stated sense, or at least require that the elimination cannot be achieved by a single adversarially chosen pair.

3. **Claim attacked:** “\(H\subseteq C_t\)”.
   **Why it fails:** \(C_t\) is the contract of \(t\)’s content, which by Part III may contain counterfactual edits \(K\). But the selection witness says each pair in \(H\) occurs as an event of the physical selection history \(\Sigma_h\). Pairs in \(K\) are defined by \(K\cap C_{\mathrm{adm}}=\varnothing\), so they cannot occur as physical events. Thus `Sel` either permits impossible events or silently assumes \(H\subseteq C_{\mathrm{adm}}\), which is not stated.
   **Severity:** serious.
   **Fix:** require \(H\subseteq C_t\cap C_{\mathrm{adm}}\), or explicitly restrict selection histories to admitted pairs.

4. **Claim attacked:** “which **eliminated at least one member** that differed from \(t\) at a pair of \(H\) on which that member failed and \(t\) did not”.
   **Why it fails:** Given the immediately preceding clause that survival holds exactly when faithful on \(H\), if \(t\) survived and some rival was eliminated, the rival failed at some pair in \(H\), while \(t\) did not. So the “difference-making condition” is entailed and adds no constraint. It does not show that the elimination discriminated against the rival *because* of its difference from \(t\).
   **Severity:** serious.
   **Fix:** require the rival to have been faithful on \(H\setminus\{p\}\) and differ from \(t\) only at \(p\), or require a pairwise contrast that is not already entailed by survival.

5. **Claim attacked:** “a variation operator \(\mu\) … that was applied at least once … and produced a member that differs from its parent at some pair of \(H\)”.
   **Why it fails:** `Sel` never requires that \(t\) or an ancestor of \(t\) was produced by \(\mu\). \(t\) can be a pre-existing member that merely survives while \(\mu\) mutates some unrelated rival. Then the provenance is filtering, not variation-and-survival production, contradicting Part 0’s “produced by variation and survival.”
   **Severity:** serious.
   **Fix:** require that \(t\), or an ancestor of \(t\)’s current transport structure, was produced by an application of \(\mu\) in \(\Sigma_h\).

6. **Claim attacked:** “no itemised representation of a defect … lies on any active route from a failure to an application of \(\mu\)”.
   **Why it fails:** In ordinary one-shot selection, variation occurs before failures are observed. Since \(\prec_h\) is acyclic, there can be no route from a later failure back to an earlier application of \(\mu\). Blindness is therefore vacuously satisfied for standard Darwinian selection. It is not a separator in the intended cases.
   **Severity:** serious.
   **Fix:** define blindness as no route from a failure to any *subsequent* application of \(\mu\), or to a later use of the variation operator; otherwise it is trivial.

7. **Claim attacked:** “an active route from a failure to an application of \(\mu\)”.
   **Why it fails:** A failure is defined as a violation, i.e. a fact that fidelity failed at \((a,b)\). Part IX defines an active route as a connected subnetwork of actual occurrences joining an occurrence that instantiates an input organization to an operative result. A failure is not an occurrence, and an application of \(\mu\) is not an operative result in the stated sense. The route condition is ill-typed.
   **Severity:** serious.
   **Fix:** define a failure event occurrence that instantiates the failed state, and define the route between event occurrences, not between a fact and an operator application.

8. **Claim attacked:** “**Non-triviality:** no event of \(\Sigma_h\) instantiates an organization held to \(t\), to \(H\), or to the survival condition by a faithful transport.”
   **Why it fails:** The “held to” relation is defined for organizations: a transport from \(D\) to \(E\) holds \(E\) to \(D\). But \(t\) is a transport, \(H\) is a set of edit–boundary pairs, and the survival condition is a predicate. None is an organization, so none can be the target of “held to” in the defined sense. The clause cannot be evaluated as written.
   **Severity:** fatal for the non-triviality conjunct.
   **Fix:** either define explicit contents for \(t\), \(H\), and the survival condition, or replace the clause with typed conditions such as “no event instantiates an organization that is a faithful transport to the content of \(t\)” etc.

   **Severity:** serious.
