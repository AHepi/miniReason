**Finding 7 — Selection as a concept can read itemised defects.**

Attacked claim: “B never reads a defect record. Its only input is a number per candidate.”

Why it fails: Selection is variation plus survival. Its feedback can be any representation. Multi-objective selection, novelty search on error vectors, Bayesian optimization with per-instance losses, and selection of hypotheses by likelihood over data all use itemised defect information. The test rules out only one B that does not. It does not establish a conceptual separation.

Seriousness: Serious.

Fix: Implement selection processes that use itemised defects. Show whether the scramble affects them as the concept predicts.

**Finding 8 — Construction as a concept can avoid itemised defects.**

Attacked claim: “The defect representation is on C's route and not on B's.”

Why it fails: A construction process can build from a world model, a problem specification, a proof, or a generative model, without itemised defect records. Under the interface reading, such a constructor would be misclassified as selection because it is invariant to the scramble. The test does not carve the concepts.

Seriousness: Serious.

Fix: Implement construction variants that do not use V. Show that the concept-level property is not tied to this one column.

**Finding 9 — C itself uses scoring and ranking, i.e., selection, so the distinction collapses or shifts.**

Attacked claim: “C — construction... B — blind selection over the meta-grammar.”

Why it fails: C's algorithm scores every condition and keeps the top 20; it solves an action by taking the best (condition, action). That is selection over hypotheses. The test therefore does not distinguish construction from selection; it distinguishes itemised-score selection from scalar-fitness selection. The conceptual distinction is not cleanly instantiated.

Seriousness: Serious.

Fix: Define selection narrowly enough to exclude C's internal ranking, or admit that the real contrast is itemised versus aggregate feedback and test that contrast directly.

**Finding 10 — M6(ii) undermines the interpretation of M4.**

Attacked claim: the scrambled run's failure shows C is using the true field as a representation of what went wrong.

Why it fails: M6(ii) shows C built a rule from records with no defect content: “Defect records with the outcome replaced by the prediction (no defect content) → **built** ... **M6(ii) ✗.**” Section 8 says: “C's accounting never checks that the old prediction differed. ... the accounting is fragile and the stopping rule can be fooled.” If C can build from no defect content, then its sensitivity to the scrambled true-field column in M4 does not by itself prove it is using the true field as a defect representation. It may be sensitive to arbitrary features of the column and fooled by the same accounting bug. The scrambled run built three junk rules with small positive nets.

Seriousness: Serious.

Fix: Fix the accounting to require that the old prediction differed; rerun M4. Add a control that scrambles the true field while preserving defect status, e.g., permute true fields among records with identical predicted fields.

**Finding 11 — “Same aggregate” is undefined and pre-ordains B's invariance.**

Attacked claim: “same states, same number of defects, same aggregate; wrong pairings.”

Why it fails: If “same aggregate” means the scalar fitness is preserved, then any scalar-fitness selector is invariant by definition. The B result is pre-ordained. If it means only the marginal distribution of true-field values is preserved, it does not establish the conceptual point. The invariant is doing crucial work and is not specified.

Seriousness: Serious.

Fix: Define the invariant precisely. Show the scramble is a pure item-level perturbation that preserves every scalar summary available to a selection process. Then the invariance is a theorem, not an experiment.

**Finding 12 — Only the outcome column is scrambled, so the claim about “the defect representation” is too broad.**

Attacked claim: “The defect representation is on C's route and not on B's.”

Why it fails: The scramble only permutes the true-field column among V records. It leaves states, predicted fields, record order, non-defect records, and the condition-induction input intact. It cannot show the entire defect representation is on C's route; it shows only that the outcome column is causally relevant to action selection.

Seriousness: Serious.

Fix: Ablate each component of the defect representation separately. Or narrow the claim to “the outcome column is on C's route.”

**Finding 13 — There are no positive controls.**

Attacked claim: “Scrambling the defect records' outcomes while keeping their number destroys C (0.906 → 0.355 on collisions); the blind process B, which never reads them, is byte-for-byte unaffected...”

Why it fails: There is no positive control showing that a known construction process with a different defect representation is affected by an equivalent scramble, nor a known selection process that uses itemised defects is affected. Without positive controls, the differential is uninterpretable.

Seriousness: Serious.

Fix: Add positive controls: a selection process whose fitness is computed from the scrambled records; a construction process that receives an equivalent non-scrambled representation. Show the expected pattern.

**Finding 14 — The process boundary is unspecified.**

Attacked claim: “B never reads V. Its only input is a number per candidate.” / “B, seed 0, re-run with the scrambled records passed in as an argument its code never reads...”

Why it fails: The fitness evaluator reads the world's true fields and computes the number. If the evaluator is part of the selection process, B does read defect information in aggregate. If it is not, then C's record collection is also external and the comparison is unfair. The test does not say where the process ends.

Seriousness: Serious.

Fix: Define process boundaries explicitly. Either include the fitness evaluator in B and test its sensitivity to scrambled defects, or exclude it from B and exclude C's record collector from C.

**Finding 15 — B's invariance is a null result with no power, and only seed 0 is reported.**

Attacked claim: “B, seed 0, re-run with the scrambled records passed in as an argument its code never reads: **byte-identical output.**”

Why it fails: A null result where the independent variable is disconnected from the process cannot falsify any hypothesis about selection. It is not evidence for selection's invariance to defect representation. Only seed 0 is reported, though the code fact would apply to all seeds.

Seriousness: Serious.

Fix: Replace with a test where B's output could change if selection uses defect representation; e.g., scramble the records used to compute B's fitness. If the result is a code fact, state it as such and remove it from the support criteria.

**Finding 16 — The C/B contrast is confounded by many other differences.**

Attacked claim: “the two processes' outputs depend on different things, which is what ‘provenance’ means.”

Why it fails: C and B differ in search algorithm, input format, rule construction, tie-breaking, population mechanics, and stopping rules. The scramble manipulates only one difference. Any differential result could be due to any of the others. The claim that it distinguishes provenances is confounded.

Seriousness: Serious.

Fix: Match processes on all other dimensions and vary only the presence/absence of the defect representation. Or use within-process manipulations: give B itemised records; give C scalar fitness.

**Finding 17 — The “wrong action” interpretation is circular.**

Attacked claim: “Under the scramble C still *induced* a near-right condition (that step reads only states, which were not scrambled) but *solved* the wrong action (that step reads outcomes, which were) — it dropped the `hold`.”

Why it fails: The author knows C's condition step reads only states and its action step reads outcomes from the code. The scramble test does not independently reveal that division of labour; it is read off the code. The interpretation is circular: C's output changed because the code uses the outcome column—that is the fact to be explained. It does not show a conceptual difference.

Seriousness: Serious.

Fix: Instrument C to log which records are used at each step. Or specify a process-level causal model and test it independently of the code's known structure.

**Finding 18 — What would have to be added to make M4 more than “C reads V and B does not.”**

Attacked claim: “That is not a claim about the code's data flow — it is a demonstration that the two processes' outputs depend on different things, which is what ‘provenance’ means in file 10.”

Why it fails: As above, M4 is currently a code-level manipulation with no conceptual reach.

Seriousness: Fatal to the conceptual claim.

Fix: Add all of the following:
1. A formal definition of construction and selection as classes of processes, independent of C and B, with an invariance property for selection and a causal-route property for construction.
2. Multiple implementations per class, including adversarial cases: selection processes that use itemised defects (multi-objective, novelty, Bayesian optimization with per-instance losses), and construction processes that do not use itemised defects (world-model, specification, proof, generative model).
3. Positive controls: scramble the true-field column for a selection process whose fitness is computed from it; show it changes. Provide a construction process with a semantically equivalent defect representation; show it builds the same rule.
4. Causal mediation/tracing: instrument C to show which defect records caused which condition and action; delete individual records and show specific rule changes; show the built rule's condition matches the defect states and its action fixes those defects.
5. Targeted scrambles that isolate defect content from column identity: permute true fields among records with identical predicted fields (defect status unchanged); replace the true field with a defect bit; supply an equivalent defect representation; show the rule changes only when defect content changes, not when the column changes arbitrarily.
6. A demonstration that the M4 effect is not due to the M6(ii) accounting bug. Fix the “fixed” criterion to require that the old prediction differed, then rerun M4.
7. A replacement for the B invariance clause. B's byte-identical output is guaranteed by an unused argument and has no power. Use a test where B's output could change if selection uses defect representation, or prove the invariance as a theorem for all scalar-fitness selectors and demote the B run to an illustration.
8. Explicit process boundaries: say whether the fitness evaluator and record collector are inside or outside each process, and make the comparison symmetric.
