**Finding 2 — S4 is a pre-registered outcome that is guaranteed by the definitions.**
- **Claim attacked:** S4: “Scrambled-V construction is worse than unscrambled on collision steps by at least 0.1, and B's output under the scramble is byte-identical to B's without it.”
- **Why it fails:** The first clause is entailed by C’s algorithm if it uses V. The second is entailed by B’s definition that it never reads V. The outcome has no power to test the provenance distinction; it is a code assertion disguised as an empirical prediction.
- **Severity:** Fatal for S4.
- **Fix:** Replace S4 with an outcome that could fail under the provenance hypothesis, e.g. an equal-access scramble.

**Finding 3 — The operationalisation is circular.**
- **Claim attacked:** §1: “remove or scramble the defect representation and the constructing process breaks, while the selecting process — which never read it — is unaffected. That is the operational content of ‘the mapped objection is on an active dependency route.’”
- **Why it fails:** This defines a constructing process as one that reads the defect representation and a selecting process as one that does not. M4 then confirms those definitions. It cannot discover whether construction and selection are distinct kinds; it can only instantiate the stipulated distinction.
- **Severity:** Fatal for the central philosophical claim.
- **Fix:** Define provenance independently of input access, e.g. by counterfactual dependence of the built machinery on defect content in novel contexts.

**Finding 4 — C versus B is confounded by algorithm.**
- **Claim attacked:** The design compares C’s route to B’s route as if the route were the only difference.
- **Why it fails:** C is greedy induction over itemised records; B is population-based mutation–selection over aggregate fitness. They differ in search operator, population size, generations, tie-breaking, and more. Even if M4 shows C depends on V and B does not, it does not isolate “route” from “algorithm.” Any fidelity difference is confounded.
- **Severity:** Serious.
- **Fix:** Use the same search algorithm with V on/off and aggregate fitness on/off; compare C to C-no-V to B to a B that has V access but no requirement to use it.

**Finding 5 — B’s byte-identical output is not evidence of selection provenance.**
- **Claim attacked:** M4: “Give B the same world — it never reads V — and confirm its output is byte-identical to the unscrambled run.”
- **Why it fails:** If B never reads V and is deterministic given its seed, identity is guaranteed. It shows no input dependence, not that B is selecting in any substantive sense.
- **Severity:** Minor as a check; serious as part of “distinguishes the provenances.”
- **Fix:** Drop or reclassify this clause.

**Finding 6 — M6 and S6 are also trivial code checks.**
- **Claim attacked:** M6: “Give C an empty V. It must build nothing. Give C V with the true field replaced by the predicted field (no defect content). It must build nothing or rules with zero net.”
- **Why it fails:** These are direct consequences of C’s algorithm. They test that the code behaves as written, not whether construction versus selection is a real distinction.
- **Severity:** Serious if S6 is used as support for provenance.
- **Fix:** Same as Finding 1.

**Finding 7 — The design has no non-trivial provenance test.**
- **Claim attacked:** §1: “the difference is checkable” and M4: “This is the test that distinguishes the provenances.”
- **Why it fails:** A non-trivial test would manipulate the defect representation while holding information access and algorithm fixed, or compare two processes that could both use or ignore it. The design has two separately specified algorithms, one with V access and one without. M3 tests translated-edit fidelity; phase 2 tests accumulation; M5 tests recoding invariance. None is a non-trivial provenance test.
- **Severity:** Fatal for the experiment’s claim to distinguish provenances.
- **Fix:** Add an equal-access test; see the final section below.

**Finding 8 — The scramble destroys the joint distribution C actually uses.**
- **Claim attacked:** M4: “same states, same number of defects, same aggregate; wrong pairings.”
- **Why it fails:** C’s action scoring uses “apply action to the state, run kinematics, prediction now equals the true field” on V records. Permuting the true-field column among V records destroys the state–true-field pairing. Any supervised learner would be affected. It tests sensitivity to labels, not whether a defect representation is on the causal route.
- **Severity:** Serious.
- **Fix:** Use a scramble that preserves the defect’s information content but changes its format/carrier, or intervene upstream on the world-to-record mapping.

**Finding 9 — Section 12.2 undermines S4’s collision-step claim.**
- **Claim attacked:** §12.2: “C, which builds from sensory defects, is expected **not to build the crossing rule**, because there are no defects from crossings; only same-target collisions… produce visible defects.”
- **Why it fails:** If C cannot build the crossing rule, then scrambling V (which contains only same-target defects) may not affect crossing-step fidelity. S4 requires scrambled-V construction to be worse on collision steps by at least 0.1. If “collision steps” includes crossings, unscrambled C is already failing them, so the scramble may not worsen by 0.1; if it excludes crossings, S4 must be restricted. This is an unaddressed inconsistency.
- **Severity:** Serious.
- **Fix:** Pre-specify collision-step subsets; ensure S4 applies to same-target collisions where C uses V; report crossing steps separately.

**Finding 10 — S5 and F1 are in tension.**
- **Claim attacked:** S5: “B reaches collision fidelity within 0.05 of C in at least 4 of 6 seeds. Same machinery, different route.” F1: “C and B reach the same fidelity with structurally different rules.”
- **Why it fails:** If the rules are structurally different, they are not “same machinery.” S5 conflates same fidelity with same machinery. Also, same fidelity does not show provenance is not output; the route difference remains stipulated.
- **Severity:** Serious.
- **Fix:** Clarify “same machinery” or drop the claim.

**Finding 11 — “Same aggregate” is ambiguous.**
- **Claim attacked:** M4: “same states, same number of defects, same aggregate; wrong pairings.”
- **Why it fails:** If “aggregate” means aggregate fitness, C never computes aggregate fitness, so scrambling V does not change it. If it means the aggregate of V records, that is not the fitness relevant to B. The phrase obscures what is held constant.
- **Severity:** Minor.
- **Fix:** Define exactly what is preserved (marginal distributions, counts) and what is destroyed (state–label pairing).

### What a non-trivial version would look like

A non-trivial scramble test needs at least:

1. **Equal access.** Both the constructing and selecting processes receive the same defect records and the same aggregate fitness.
2. **Same architecture.** They differ only in the update rule: one conditions on itemised defects, the other on aggregate fitness.
3. **Intervention.** Scramble the defect records for both, holding aggregate fitness fixed.
4. **Prediction.** The constructor’s output changes; the selector’s does not, despite equal access.

That would show the route is doing causal work. Alternatively, a **counterfactual defect-transfer test**: build from defects in W1, then test on W2 where surface statistics are matched but the underlying law differs. A constructed component should carry W1-specific defect information; a selected component should track W2’s fitness. The design has no such test. M3 tests translated-edit fidelity; phase 2 tests accumulation; M5 tests recoding invariance. So no, the design does not have a non-trivial version of the scramble test.
