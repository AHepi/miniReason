## Serious

**1. The S0 baselines were selected on the evaluation (test) half.**
- Claim attacked: §1's table row "S0: best of old grammar G0, any kind — `lookup(k=2)`" (0.819 collision) and "S0: best *structured* G0" (0.366), plus §9's "**S1 needed** — 0.906 > 0.819 (best G0, a memoriser) > 0.366 (best structured G0)."
- Why it fails: `g0_best(history_exposure, history_evaluation)` builds each architecture's lookup table from exposure, then takes `f, _ = evaluate(a, table, history_evaluation, NUM_CELLS)` and `if best is None or f > best[0]: best = (f, ...)`. That is model *selection* by test-set score. `best_slot_only` is likewise chosen by collision-step fidelity on `history_evaluation`. So 0.819 and 0.366 are maxima over the architecture set on held-out data — optimistically biased, not clean baselines. The bias favours the baseline, so S1's direction survives; the *magnitudes* do not.
- Severity: serious (integrity of the headline comparison).
- Fix: select the architecture on a validation split carved from the exposure half (or by an exposure-only criterion), freeze it, then report its evaluation score; report the full architecture distribution rather than only the winner.

**2. "B is byte-identical under scramble" is a tautology, and it is reported as evidence.**
- Claim attacked: abstract — "the blind process B, which never reads them, is byte-for-byte unaffected"; §5 — "B, seed 0, re-run with the scrambled records passed in as an argument its code never reads: **byte-identical output.**"; §9 — "✅ **S4 on the route** — scrambled C worse by 0.55 (threshold 0.1); B byte-identical."
- Why it fails: `ignored_records` is a parameter of `blind_search` that is never referenced anywhere in the function body. The "test" is `blind_search([], exposure, 0, ignored_records="scrambled records passed and ignored")` — same seed, same data, same deterministic code. It cannot fail. §5 concedes the mechanism ("an argument its code never reads") but §9 and the abstract still cite the outcome as support. Additionally, the check performed is `[rule_name(r) for r in b_rules_again] == R["B"][0]["rules"]` — equality of rule-name *string lists*, not bytes; fitness dictionaries and round logs are not compared.
- Severity: serious (an empty result is presented as half of S4's support).
- Fix: delete the empirical claim and restate it as a design argument (B's interface is a fitness function over exposure histories, so there is no slot for records), or run B in a separate process that exposes only a fitness callback; and replace "byte-identical" with "identical rule list."

**3. F2 / "C stops" is only verified over 20 of 3,136 conditions.**
- Claim attacked: §2 — "Round 2: 1,266 defects remain; **no condition–action pair has positive net; C stops.**" and "C correctly declines to invent one"; §9 — "F2 — C stopped at one rule with 1,266 residual defects … report, no more rules warranted."
- Why it fails: `scores.sort(reverse=True); top = scores[:top_m]` with `top_m=20`, over `len(CONDITIONS)` = 56 atoms + 1,540 AND-pairs + 1,540 OR-pairs = 3,136 (minus those with `tp == 0`). The action search never runs outside the top 20. The true statement is "no positive-net pair among the 20 conditions ranked by tp−fp." A condition ranked 21st with a positive-net action — e.g. a precise low-support condition for the change-step/co-location residuals — would be invisible. So "C correctly declines" is unestablished.
- Severity: serious (the stopping claim is a headline).
- Fix: dump the full round-2 score list (or the top 50 plus the best net outside the top 20) and re-run with `top_m = len(CONDITIONS)`; report where the true optimum ranks.

**4. The condition score `tp - fp` ignores base rates, and tp/fp are never reported separately.**
- Claim attacked: §2 — "Condition induced: `n_i == n_j` (score 929)."
- Why it fails: `scores.append((tp - fp, -condition_atoms(cond), idx))` is computed over |V| = 2,830 and |N| = 4,778. Score = support × (2·precision − 1), so coverage and precision are conflated; a high-support mediocre-precision condition ties a low-support perfect one. The ranking that fixes the top-20 cut therefore depends on the raw |V|:|N| ratio and on the record-collection threshold. And only the difference (929) is reported, so coverage and precision are unauditable.
- Severity: serious (it is the selection mechanism behind findings 3 and 5).
- Fix: report tp and fp for the induced condition and at the top-20 boundary; use a base-rate-aware statistic or justify `tp − fp` against a permutation null.

**5. Everything is hard-coded to exactly two things; "one rule suffices" is a 2-body artefact.**
- Claim attacked: §11 — "One world, one rule language, one constructor" — as the scope statement for the whole §1 result; and §1's claim that "C's single rule reproduces the hand-built pair exactly."
- Why it fails: `A0 = {..., "num_slots": 2, ...}`; `apply_rules` loops `for i, j in ((0, 1), (1, 0))`; `world_step(things, laws)` unpacks exactly two things. The world, the predictor, and the rule language are all 2-body. With three things a same-target 3-body collision is inexpressible (a pairwise condition selects one pair; the language fires once per step), and the code cannot be run with three slots at all. Failure mode 7 covers firing order *within a pair*, not the n-body limit.
- Severity: serious for any claim about construction in general (the file's own scope caveat "one world" does not cover the stronger structural restriction).
- Fix: list the pairwise/two-thing limitation explicitly; run a 3-thing world to test whether the pairwise language composes.

**6. No internal holdout for rule acceptance — and the scramble itself re-triggers the M6(ii) accounting leak.**
- Claim attacked: §10 FM6 — "C accepts every rule with positive net on exposure records"; §5's scrambled run — "3 rules: `(c_i == c_j) OR (n_i == n_j) → swap_next_v` (no hold) ×2, then a patch"; §8 — "In the real run that invariant is guaranteed by how records are collected."
- Why it fails: (a) candidate scoring and rule acceptance share the same exposure records, so `net` is in-sample and the stopping rule can be met by noise — the scrambled run's three junk rules are exactly that symptom, but the file attributes them to FM3 (accounting) rather than to in-sample acceptance. (b) Sharper: §8's invariant "old prediction differed from outcome" holds only for the *unscrambled* pairing. `scramble` permutes `rec[3]` among V, so for any record whose shuffled outcome happens to equal its own pre-rule prediction, a rule that changes nothing counts as `fixed`. Part of the 0.55 collision drop is therefore the accounting leak re-triggered by the scramble, not pure route-dependence.
- Severity: serious (S4's mechanism is confounded, though 0.55 ≫ the 0.1 threshold so the verdict likely stands).
- Fix: re-run the scramble with corrected accounting (require the pre-rule prediction to differ from the outcome inside the `fixed` count) and report the corrected drop; add a leave-one-configuration-out validation split for rule acceptance.

## Moderate

**7. The phase-2 wall law is inexpressible in this rule language, so §7's "hand-built" reference is not correct either.**
- Claim attacked: §7 — "A0 + phase-1 + hand-built wall rule | 0.808 | 0.769" presented as the correct reference against C's 0.773; §9 — "wall rule built ✓ (right condition, wrong action)."
- Why it fails: §8 reports `stop_both + hold` and `swap_next_v + hold` tie at net 952 with 27 broken, and `stop_i + hold` scores only 540 "because a rule fires once per step in the first matching order, so when both things hit walls at once it can stop only one." But `HAND_WALL = (... ("stop_i", True))` — the reference rule *is* the handicapped `stop_i`. And `stop_both` is also wrong (it zeroes the velocity of a thing that did not hit a wall — hence the 27 broken). No correct wall rule exists in the language. So §7 contrasts two compromised rules, and "right condition, wrong action" understates a language limitation. Phase 2 is confounded twice over (FM10's design confound plus this).
- Severity: moderate (S7's verdict is mis-attributed).
- Fix: report the best achievable wall-rule fidelity in the language as the reference, and re-label C's phase-2 failure as partly inexpressibility; or extend the language to per-slot firing before re-running.

**8. The ceiling is an in-sample oracle on the evaluation half, and the expressibility check therefore passes trivially.**
- Claim attacked: §1 — "Sensory ceiling (in-sample, for scale) | 0.900 | 0.923 | 0.895"; `run_controls` — `out["expressibility_check_passes"] = hand["collision"] >= 0.9 * out["ceiling_evaluation"]["collision"]`.
- Why it fails: `ceiling_split(evaluation)` keys on `tuple(s["sensory"] for s in seq[:t+1])` and takes the majority next *true* field **from the evaluation half itself** — a memoriser over test prefixes. No exposure-trained system can reach it, so sitting it beside C's 0.906 invites a "near-optimal" reading that is not available to any learner. Worse, the hand-built crossing rule has *zero* sensory effect (a cross and a pass-through occupy the same cells), so the expressibility bar is satisfied by the same-target rule alone and tests nothing about the language's expressive power.
- Severity: moderate.
- Fix: compute a cross-validated or exposure-only ceiling; move the expressibility check to the M3 level, where the crossing rule actually matters.

**9. The scramble permutes only the outcome column — states and defect-set membership are preserved, and the induced condition is logically unchanged.**

The test therefore shows that the outcome *pairing* matters, not that the defect representation as a whole is on C's route.
- Severity: moderate (the inference is narrower than stated).
- Fix: add a second manipulation that also permutes states among records (or permutes defect-set membership) and report which manipulation drives the drop.
