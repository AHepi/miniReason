The passage under attack is: “**C never computes an aggregate fitness. Its only inputs are itemised records.**” and the companion: “**B never reads a defect record. Its only input is a number per candidate.**”

## 1.

**Claim attacked:** “C never computes an aggregate fitness. Its only inputs are itemised records.”

**Why it fails:** The text immediately after gives C an explicit scalar objective: “score every condition in the language by (number of V states it is true on) − (number of N states it is true on); keep the top 20.” That is a sum over records. It is used to rank conditions and select candidates. It is a fitness function. It is itemised in its input representation, but aggregate in its computation. The same is true of the action score: “count the V records it fixes … minus the N records it breaks. Take the best (condition, action).” A scalar used to rank and take the best is a fitness.

**Severity:** Fatal to the stated distinction.

**Fix:** Replace “C never computes an aggregate fitness” with “C never computes a global black-box architecture fitness; it computes a local, structured fitness over rule components from itemised records.” Then the contrast is local/structured vs global/black-box, not aggregate vs non-aggregate.

## 2.

**Claim attacked:** “Its only inputs are itemised records.”

**Why it fails:** C also uses the current architecture, the kinematics, the fixed meta-grammar, the exposure half, the N records, and the tie-breaking order. More importantly, the itemised records are transformed into aggregate counts before any selection occurs. The sentence describes the data format, not the computation.

**Severity:** Serious.

**Fix:** Say “C’s input data are itemised V/N records; its selection criteria are aggregate scores over those records.” Do not use “only inputs” as a differentiator.

## 3.

**Claim attacked:** “B never reads a defect record. Its only input is a number per candidate.”

**Why it fails:** B’s number is “**exposure-half** fitness of the current architecture plus the candidate rule.” That fitness is computed from the same per-step predictions and true fields that generate C’s defect/non-defect records. It is an aggregate function of the current architecture’s errors. B does not see the individual tuples, but it is not defect-independent. The difference is interface compression: C gets the itemised error tuples; B gets a scalar sufficient statistic of them.

**Severity:** Serious.

**Fix:** Say “B receives only a scalar summary of the current architecture’s errors; C receives the itemised error tuples.” Do not say B does not read defect content.

## 4.

**Claim attacked:** The M4 scramble test as a provenance test: “Give C the exposure half’s defect records with the **true-field column permuted** … Give B the same world — it never reads V — and confirm its output is byte-identical to the unscrambled run. **This is the test that distinguishes the provenances.**”

**Why it fails:** B is defined as a process that never reads V. Its “byte-identical” outcome is therefore analytic, not empirical. The test does not show that B lacks a representation of the defect; it shows that B’s input interface excludes the scrambled file. To test whether B uses defect content, you would have to scramble the true fields in B’s exposure half or give B the same V and see whether it uses them. The current design confounds “does not receive this representation” with “does not operate on any defect representation.”

**Severity:** Fatal for M4 as a provenance test.

**Fix:** Define a common information set. Scramble the underlying true labels for both processes. Or add a B+V condition where B receives the same records but can only convert them into a scalar. If B+V still equals B, then the representation is not on B’s active route. Also add a C control with an equally rich but irrelevant record type.

## 5.

**Why it fails:** If both processes search the same fixed 50,176-rule meta-grammar, and B is expected to reach the same fidelity, then the rules are latent in the grammar. **Severity:** Fatal to the strong provenance claim.

**Fix:** Reframe the experiment as a comparison of search operators and inductive biases. If you want construction in a stronger sense, require C to produce new predicates, new terms, or new representations not already present in the fixed meta-grammar.

## 6.

**Claim attacked:** The implicit claim that C’s condition score is not a fitness.

**Why it fails:** `(number of V states it is true on) − (number of N states it is true on)` is a signed classification objective: true positives minus false positives. The action score `fixed(V) − broken(N)` is a counterfactual reward over records. Both are aggregate objectives.

**Severity:** Fatal to the wording “C never computes an aggregate fitness.”

## 7.

**Why it fails:** “No V remain” is an aggregate stopping criterion. It counts residual defects. Combined with “keep the top 20,” C uses multiple aggregate criteria even if one refuses to call the condition/action scores fitnesses.

**Severity:** Serious.

## 8.

**Why it fails:** The selecting process is defined as one that never read the representation. Its unaffectedness is true by definition. This is circular as an operational test. It does not discover a difference in provenance; it encodes the difference in the input plumbing.

**Severity:** Serious to fatal for that operationalization.

B’s mutation operator receives no per-state credit; it only sees a scalar per complete candidate. That is a real difference in inductive bias and sample complexity. But it is not beyond efficiency/information in the strong sense: B’s scalar is computed from the same per-step errors, and with enough evaluations B can find the same rules in the fixed meta-grammar. S5 expects exactly that. The difference is algorithmic guidance, not a different kind of process. If “operates on a representation” means the representation is causally necessary for hypothesis generation, then yes for C and no for B. If it means a different provenance kind, no.

**Severity:** Serious overclaim.

**Fix:** State the weaker claim: C uses a structured error signal for credit assignment and hypothesis generation; B uses a black-box scalar. Then design an experiment that isolates this from raw search budget—e.g., match evaluation counts, give B the same records only through a scalar wrapper, and test whether C succeeds where B fails at equal budget. Do not call it “construction vs selection” without that.

## 11.

**Claim attacked:** The contrast between C and B as “aggregate vs itemised.”

**Why it fails:** B’s fitness is an aggregate over exposure configurations. C’s condition and action scores are aggregates over V/N records. Both aggregate. The real contrast is global architecture-level objective vs local component-level objective. Using “aggregate” as the differentiator is equivocation.

**Severity:** Serious.

**Fix:** Use “global architecture fitness” for B and “local component score” for C. Drop “aggregate” from the distinction.

## 12.

**Why it fails:** Even under that charitable reading, C still selects rules greedily by local aggregate scores and stops on an aggregate residual-defect count. The distinction from B then becomes objective scope and search procedure, not the presence or absence of aggregation. The document should not use the unqualified sentence as if it marked a kind difference.

**Severity:** Serious.

**Fix:** Qualify every claim about aggregation by its unit: records, conditions, actions, or architectures. Then state explicitly that C optimizes local component scores and B optimizes a global architecture score.
