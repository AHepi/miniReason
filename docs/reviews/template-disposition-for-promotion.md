## The required boundary between templates

The recommended boundary agrees with the parallel handoff review: `joint_construction_v1` runs one construct/criticize/revise/promote episode; a proposed `successor_discrimination_v1` then runs one locate/discriminate episode. The second investigates target, provenance and competing readings and returns a warranted successor question or suspension/no-promotion. It does not run another joint-construction episode. These are prospective contracts, not a claim that the new adapter already exists or has run.

The first template should complete its own one-cycle contract and preserve its full results before the next template starts. The second should have a different declared job: investigate a nominated uncertainty, its grounds or the proposed promotion itself. Its identity must follow from different stage instructions and input/output obligations, not a new label on the same loop. Separate plans, logs and an explicit parent occurrence/hash link make that distinction recoverable.

The handoff is an observable mechanism only if the second template actually consumes the first template's selected output through the declared input route. A host queue entry by itself is not operative return. The complete first output should remain available for auditing a selected passage; any extraction or summarization is a separate fallible transformation whose source and policy must be declared. Direct and Mini comparisons need the same relevant opportunity to inspect that material when orchestration is the claim.

A missing substantive successor is an admissible result. The first template may recommend no promotion; the second may find that an apparent issue was resolved, inherited, wrongly attributed, unsupported, or still worth investigating under a revised question. None of these requires automatic acceptance, refutation, scalar priority or language installation. Host checks can bind identities and budgets while leaving substantive reasons in legitimate prose.

The outstanding reason-use block can affect what the next chain needs to test. If E020 answers the supplied arithmetic without its account, that would be a bounded observation about this use task and would strengthen the reason to choose a different dependency for the promotion chain. If E020 differs, inspect the exact changed claims and finite premises; a changed answer alone does not identify account necessity or a Mini mechanism. E021 can complete the omitted-supplemental-criticism condition, but its source packet still contains earlier reasons. Neither possible outcome warrants another indiscriminate carrier sweep.

This review supports a concrete next mechanism, not closure of the whole research program. Final activation remains with the publisher after E021/E020 preservation and review and the separately specified handoff design.
