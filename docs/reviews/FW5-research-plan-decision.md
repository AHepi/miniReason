# Proposed research-plan update from the actual FW5 source

Decision ID: DEC-20260912-FW5-PLAN. Status: proposed, awaiting the user's approval. No research-plan, frozen experiment, runner or semantic-source amendment has been implemented.

**Recommendation: update the source mapping and next research priorities; retain the programme, controls and historical evidence.** The goal remains exploring Mini's configuration space and testing the supplied account of explanatory creativity for gaps. The update should make explicit which source is being tested and move the next substantive study toward construction with actual use and operative return.

The user-designated source is [FW5: Explanatory construction](../sources/FW5-explanatory-construction.md). Root and an independent reader each read all 1,502 lines, including the mathematical constructions, reconciliation, defeat conditions and source register. The independent reader challenged the draft recommendation to distinguish existing agenda ideas from new priorities and Origin from stronger deployment claims; those cautions are incorporated here. An exact copy is archived solely as evidence for this assessment; that archival act does not adopt a revised research plan. The exact supplied reading-copy SHA-256 is `8105925b07db4a17f15c38cbad79aaca16653d94b0503de79756b5ece33ee63a` (142,113 bytes). Its editorial introduction identifies the historical manuscript as ECS 1.0 and states that the renamed reading edition is not a new scientific revision. This is not a claim that its bytes match an unavailable original ECS 1.0 file; the hash identifies this uploaded reading edition.

The current [PURPOSE](../../PURPOSE.md) and [semantic guide](../SEMANTIC_GUIDE.md) name ECS 2.0. ECS 2.0 calls itself an audit-revised successor, so this is a substantive version distinction. The attachment supplies the full FW5 source for comparison; it does not automatically validate every later amendment or reconstruct the successor PDF's missing formulas. The proposal is to name FW5 as the designated research source and retain ECS 2.0 as a separately identified successor whose additions remain hypotheses. The harness specification remains a mechanism reference, with no power to redefine FW5.

Much of the existing plan is already consistent with this source. [The agenda](../RESEARCH_AGENDA.md) already proposes content-preserving recoding, changed-content and omission controls, nontrivial construction, protected uses, distinct successor questions and later operative integration. [The formal-feedback protocol](../FORMAL_FEEDBACK_PROTOCOL.md) already keeps prose legitimate and distinguishes formal validity from interpretation and bearing. These are retained safeguards, not new discoveries from this review. No reason was found to discard prior observations merely because the designated source has now been clarified. Their original plans and attribution limits remain the terms on which they ran.

The necessary change is the priority and interpretation of the next work. The current A-to-B chain asks whether a new episode can locate and discriminate a proposed issue in an earlier construction bundle. That remains useful bounded evidence. It does not, by itself, test retained deployment or the source's recursive closure under every admitted finite chain. A statement that proposed changes were not installed is also insufficient to prove that no represented interpretation changed: actual use must be investigated, not inferred from host flags either way.

For the next construction-and-use study, first identify the exact relation it is intended to construct and why a downstream task calls for that relation; select the task before examining its new responses. A forced choice among supplied finished solutions cannot be credited as unrestricted construction. A controlled contrast in which the relation is unnecessary or redundant remains informative, but cannot silently stand in for the needed-use case—the existing E023 arithmetic result illustrates why this distinction matters. If the task cannot support a defensible material-to-semantic mapping, revise the proposed task or report the attribution unresolved rather than strengthen the result.

The attributed organization should ordinarily include the model, Mini, operative configuration and admitted tools. Operator-supplied decoders, formal languages and information must be named as contributions. Attribution to the model alone requires a separate account. A public argument is evidence about that artifact and its configured use, not a view of hidden native reasoning. Source-faithful candidate explanations and subsequent use should be assessed alongside adverse cases: valid feedback ignored, an invalid objection actively used, an apparent repair that loses a protected achievement, and a criticism that properly leads to retention or suspension. These are possible distinguishing cases, not mandatory participant fields or a numerical score.

FW5's Attempt + New + Build origin predicate allows a false conjecture to be originative. Repair and created explanatory knowledge demand additional facts, including an attributable change, preserved protected obligations, an adequate contribution and subsequent deployment. The plan should keep these claims visibly separate in results. Unknown earlier deployable repertoire leaves historical New unresolved; a fresh string or a clean run directory cannot resolve it. Progress can be changed use of an existing capability without a larger endpoint task set.

The return must concern the same parent's operative use, interpretation, method or attention under a stated correspondence. Suspension or withdrawal can be an operative change; code installation is not mandatory. At least one relevant alternative subsidiary result must permit a different use-state, unless the contract establishes only one applicable use. The actual interpretation, attention practice or critic policy can itself become the target. An interpreted active route remains an additional requirement beyond endpoint contrasts; redundancy means no-return invariance alone cannot establish absence of use. The return intervention would test a finite instance, not prove recursive capacity. Fixed weights are not by themselves a domain barrier, and permission to edit every parameter is not universality. Constructor theory remains part of the source's capacity account: a finite successful run can witness a lawful occurrence or a bounded task performance, not an arbitrarily improvable retained capability or universal creative capacity. Keeping those stronger attributions unresolved must not prevent useful finite configuration research.

FW5 supplies a particular theory risk: an independently defensible non-explanation satisfying all Account conditions would challenge sufficiency; a genuine explanation for which no interpretation preserving its actual organization can satisfy them would challenge necessity. Failure of one selected encoding or grain is not that necessity result. A counterexample must not be repaired away by silently changing the question, grain, boundary or anchors after the failure. The source also names representation/integration challenges (decorative reasons wrongly admitted or genuine inexplicit understanding excluded) and knowledge-creation challenges (all clauses passing without the claimed epistemic repair, or genuine knowledge creation excluded). These remain distinct attack branches; the first Account case is a priority, not the entire theory-testing programme. Gap-filling amendments should be separately proposed and exposed to the same criticism.

The pending implementation scope, if approved, is to revise PURPOSE, SEMANTIC_GUIDE, RESEARCH_AGENDA and relevant source/experiment-method navigation to state this mapping and priority, then prepare the concrete construction-and-use study and the separate semantic challenge before any new live request. The 16-condition rule-routing diagnostic can remain a narrow engineering option. Formal feedback remains optional and detachable. Neither should become the whole programme or be promoted to a creativity test by its label. No budget, new provider call, automatic third episode or automatic E025 rerun is selected by this decision note.
