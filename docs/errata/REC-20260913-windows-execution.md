## Concurrency correction for future scheduling

The user's clarified limit is **up to five dependency-ready arms concurrently**, with **at most five active DeepSeek requests across all arms**. This is independent of the Codex limit of four live agents including root. A provider slot is not a Codex agent slot, and neither limit requires one template to finish before an independent branch can proceed.

Start independent branches, including branches within nonlinear templates, as soon as their own frozen-plan dependencies and publication gates are satisfied. Keep each arm's causally dependent stages ordered. One publisher serializes Git updates; it does not globally serialize model execution. Gate each dependent dispatch on its own committed, published and verified inputs, subject to the actual frozen plan and any stronger run-specific guard.

H002 completed six calls under its frozen sequential, no-retry plan. Its two post-prefix branches could have overlapped under a different prospective schedule; serial execution was an unnecessary scheduling choice, not a provider limitation. Preserve the historical plan, timing and results. Apply the correction only to a separately declared future schedule; do not rerun H002 or retrospectively relabel it concurrent.
