# Method lessons

Switching provider thinking mode does not isolate a single internal mechanism. DeepSeek's documented sampling behavior differs by mode. Record the actual mode and use within-mode Mini versus matched-control comparisons for stronger attribution.

A machine checker can test a finite operational obligation while leaving the accompanying explanation inadequate. Store these outcomes separately. Neither a larger count of passing examples nor an unchallenged output is a creativity certificate.

The initial reservation probes exposed the nested encoding channel as a major candidate-failure locus. For the next study, expression in a proposed language is the object of investigation; syntactic executability and correct capture cannot silently become its acceptance gate. Preserve prose, declared inability, attempted constructions and criticism separately, and freeze initial material before inventing languages to prevent a language from selecting only convenient examples.

E004 demonstrates why setup output needs inspection before calling a later reader blind: a source-conditioned language can quote or pretranslate the source even when instructed not to. Freezing the whole packet preserves this initial specimen, but a later reader's reconstruction can draw on the language itself. Keep source-field withholding, actual information independence, and prose-escape copying distinct.


## 2026-09-12 — Need-for-state does not establish candidate-account use

The [SQL construction protocol](../SQL_CONSTRUCTION_RETURN_PROTOCOL.md) supplies two permitted database states with exactly the same visible old view and next event but different required successor output bags. This establishes an information limit at that declared route before observing a model. It prevents treating an already cued use question as if it required the candidate relation, as the E023 review warned. It does not establish that one particular candidate account is necessary: different sufficient states or direct reconstruction from original tables can resolve the ambiguity. The full-source reconstruction comparison remains separate from archive/no-return.

Task material separation is not actual prompt separation. The generator keeps hidden histories, oracle outputs and the distinguishing relation outside the participant packet. Only a later allowlisted prompt builder and actual-wire inspection can establish that those operator materials, case labels or earlier contexts were not delivered. An empty account field cannot implement no-return if hidden histories remain elsewhere in context. The material-only tests deliberately leave that integration claim pending.

A rigorous but long mathematical calculation is not an Account counterexample merely because a shorter proof is illuminating. In [the skew-matrix challenge](../reviews/FW5-account-skew-matrix-challenge.md), the exhaustive expansion contains the parity/skewness cancellation that supplies the original obstruction account. This local failed attack gives a more specific requirement for the next search: independent absence of bearing must survive the actual organization and respect, not rely only on presentation quality. It does not confirm FW5 or settle all mathematical explanation cases.


## E027: state decoder and update deltas are different observation routes

The [three-sample SQL comparison](../reviews/E026-E027-construction-comparison.md) supplies a concrete distinction. The exact-prompt control updates its retained value bags/counts sufficiently for its declared decoder but omits NULL-extension swaps from its stated signed deltas. The selected account has correct immediate output deltas for NULL-key left deletion under a literal reading while retaining an obsolete left row; later reconstruction exposes the inconsistency. The observation route changes which obligation the finite evidence tests.

Identify cached-output updates, complete state decoding and retained-state meaning before issuing a verdict. A correct endpoint does not settle every commitment, while an omitted written operation need not prevent a prose interpreter from supplying it. Preserve that contribution explicitly. Right-ID sets preserve projected multiplicity; value sets do not. Under legal full-before-image events, right-ID retention is not required to recover a deletion's key/value. Data structure and event-information choices therefore belong in configuration and attribution records.

Criticism-return testing must allow the initial interpreter to resolve an omission before criticism. If it does, later correct use is not automatically criticism-induced repair. E028 preserves a shared actual first use and criticism and then varies only criticism delivery into the apply stage; replayed public prefix responses must not be counted as newly generated calls. A finite difference still needs substantive interpretation, and identical outputs can leave influence unresolved.

## H002: finite state, source attribution and parent continuity

The [completed H002 root review](../../experiments/diagnostics/H002-deepseek-routing/REPORT.md) separates exact event-state preservation from criticism validity and continuation meaning. Every extracted finite field matched, yet the critic attributed its own instruction to U0, the returned branch accepted unsupported source claims, the archived branch reinterpreted a completed parent as a pre-event replay, and both fresh-use answers contained contradictory prose. A transport-success receipt and a correct endpoint cannot settle those distinct obligations.

Treat a missing field in one stage's view as a visibility limit, not proof that the public record lacks it. Preserve which occurrence actually supplied a sentence, rule, initializer and event position. A proposed replay may converge numerically while still misdescribing the operative parent; inspect that claim independently. Uptake of criticism can propagate an error without changing a finite answer. These observations motivate content-sensitive and parent-continuity contrasts, but do not themselves establish a Mini advantage or criticism-induced repair. Prior source-conditioned language mappings similarly belong to the admitted instrument when evaluating later prose conversion; reproduction alone does not establish new invention or unfamiliar-source generalization.


## 2026-09-19 — Cross-examination of the FW5 rewrite and two frozen experiments

Evidence: [the adjudication](../reviews/2026-09-19-fable-cross-examination/15%20Adversarial%20cross-examination%20-%20findings%20and%20adjudication.md), [errata for experiment 1](../reviews/2026-09-19-fable-cross-examination/16%20Errata%20-%20experiment%201%20after%20cross-examination.md) and [experiment 2](../reviews/2026-09-19-fable-cross-examination/17%20Errata%20-%20experiment%202%20after%20cross-examination.md), with the frozen designs, results, code and diagnostics in the same folder. Two outside models (deepseek-flash, Atria-Dawn-Preview) acted as witnesses; the author adjudicated. Scope: one six-cell world, one rule language, one adjudicator.

**An author adjudicating findings against their own work softens verdicts wherever a repair is in mind.** Three audit passes over the adjudication found the same pattern: findings valid against the text as written were marked "partly valid" because a fix existed, and non-verdicts ("accepted for experiment 3", "did not bite here") deferred a ruling on the current claim. Rule: the verdict is on the text as written; the repair goes to a change list; a finding accepted for a future experiment is valid against the current one. The opposite audit (over-concession) found four repairs in the change list that contradicted each other, which the per-section lists had hidden. Consolidate repairs before revising.

**A "beats the memoriser" result needs a memoriser with fall-back, majority vote and a non-degenerate default.** Experiment 1's lookup baseline used only the exact last-k key, predicted an empty field when the key was unseen, and kept the last continuation seen. A fair k = 3 memoriser scored 0.801 on held-out configurations against the selected tracker's 0.801. The reported 0.145 gap was the baseline's construction. Report per-k ceilings; an in-sample full-prefix majority predictor is an oracle, not a bound on what can be learned.

**Instrument whether the parameter under test ever acts.** The four-way tie among persistence values on the one-thing history was forced by the winning search radius (5, spanning the line): the unconfirmed count never exceeded zero, so the forgetting parameter was never consulted. A tie that is a consequence of the architecture grammar is not a neutrality finding about the world. Count the events on which the parameter could act and report zero as a design fact.

**For architectures that do not learn from exposure, the evaluation half is the selection set.** An exposure/evaluation split defends only the learned component. Exhaustive selection and a later "the search lands on the same architecture" check were the same statistic. Use a three-way split (exposure, selection, confirmation) or cross-validate and report variance; a 0.003 winning margin was systematic here (38 configurations won to 14 lost, on both halves) but that had to be shown.

**Check that two metrics differ and that every condition does something.** M2 on H_full was the same number as M1 on H_full for all 208 architectures; the swap change was bit-for-bit the identity change in all 171 configurations and doubled the weight of "nothing happens". Both were visible in the raw JSON.

**A scramble is a manipulation and needs a manipulation check.** Permuting outcomes across records left the state→outcome map intact for two of five seeds because states recur; the original one-seed effect was partly luck. Verify with mutual information and defect counts, run several pre-registered permutations, include a placebo column and a known-corruption control, and prefer within-state permutations. A control that passes an argument the code never reads is not a control.

**"Itemised versus scalar feedback" can be analytic.** A scalar can be a sufficient statistic of the records (a likelihood), in which case the contrast is about credit route, not information; or it can be chosen invariant to the manipulation, in which case the prediction is entailed. The experiment that could fail includes a sufficient-statistic scalar cell as the critical control and matches information, not only budget.

**A frozen stopping rule has no warning category.** "Phase 2 only if S1–S6 hold" was breached when S6's second clause failed and phase 2 ran anyway under a "⚠️" the design never defined. Post-freeze diagnostics are breaches of "no measurement is added after freezing"; label them and never let them support a frozen claim. Hash and timestamp the design at every change, not once at freezing — otherwise the artefact cannot prove that a change preceded the run.

**Given-bound conditioning discards post-treatment failures.** The thing-tracking test counted only pairs already bound at the change step, and the code emitted passed/total while the report quoted the conditional figure, which no output contained. Emit and report both denominators; score from the step after the injected change, since the change step itself is a tautological pass.
