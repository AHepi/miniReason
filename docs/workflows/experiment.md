# Run and diagnose one configuration

A test starts with a question about expression, use or repair, an original configuration rationale, a named task family and explicit comparison arms. Initial model-proposed languages and semantic classes are frozen specimens; correctness of capture is not their admission gate. A Lean-oriented or non-Lean proposal, and a prose criticism lacking formal translation, remain legitimate material for the study. State which observation route is being tested and retain the complete original content. A later configuration must name its causal parent or state that it probes an independent mechanism. Random template mutation is outside this project.

Check that every stage exists, every required port reaches the intended artifact in the intended cycle, and commitments are rendered wherever a later stage must inspect them. Inspect the compiled manifest and representative rendered prompt. A declared port that is not selected by the stage does no work. State whether commitments require one or two calls; do not infer call counts from stage counts.

Keep the bare and native arms free of Mini's orchestration. Give matched multi-call controls the same task information and external feedback where the comparison concerns orchestration. Separate unequal-allowance practical comparisons from causal mechanism comparisons. Do not choose whichever intermediate artifact the evaluator happens to prefer; the output-selection rule is fixed in advance.

Freeze initial proposal text, any interpretation or undeclared maps, rendering, tools, settings and resource conditions before the first trial. Integrate later changes only as separately identified successors. If a prior scheme or artifact is supplied to a comparison, keep its exact content and evidence equal across relevant arms.

Preserve final answer text even when parsing fails. A transport, schema, wiring, no-result or checker failure is an operational event with plural possible causes. A valid candidate that violates a named task obligation is a task failure under that interpretation. A successful task check is neither a full explanation audit nor a creativity certificate.

Afterward write the complete record, including settings and actual resource usage, and diagnose every failure in the errata. Add lessons only when they have evidence and state how widely they apply. Read explanations independently of scalar task success. Commit and push immediately, verify the remote identity, and only then start a successor configuration.
