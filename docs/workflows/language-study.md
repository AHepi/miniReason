# Frozen language study

Start with PURPOSE, STATUS, LANGUAGE_PROPOSAL_THEOREMS, PROBLEM_PROMOTION and EXPRESSION_ANALYSIS. The active question is relative expressibility and later creative construction. Semantic capture and Lean compilation are not initial admission gates. All prompts are original miniReason work.

## Freeze the materials in order

Use `python -m minireason.language_study --help`. The `prepare-plan --stage corpus` command freezes a problem and instructions for one model call producing the initial prose. Commit and publish the plan before using `prepare`. Publish the completed preparation record, including failures, immediately. The emitted `corpus.json` is the immutable starting material. Do not repair or summarize it into a convenient specimen.

Next use `prepare-plan --stage languages --corpus <completed-corpus.json>` to request a paired Lean-compatible language and non-Lean semantic class. Publish the plan, run `prepare`, and publish that completed record. Packet extraction uses two string fields as transport boundaries; a malformed response retains its public bytes and is an extraction failure, not a rejected argument. Do not retry it silently. The model chooses the expressive system; the host provides no inherited template or prescribed operator inventory.

Read the actual `packet.json` before designing probes. Record source quotations or ready-made translations inside language declarations as possible information leakage. A language invented from the corpus is source-conditioned even when no literal quotation appears. Preserve both original languages, source corpus, model identity and origin hashes. Correctness is not a requirement for freezing a packet.

## Preregister one carrier comparison

The `plan` command takes `--packet`, `--carrier prose|lean_candidate|nonlean_candidate`, `--rationale`, optional `--parent`, `--arms`, `--max-tokens`, and an output path. It records exact prompts, resource settings and source identity. Publish the plan before `run --plan <plan.json> --output <new-record-directory> --jobs 5`. Every output directory must be new. No more than five live model calls run within a process; run only one such five-worker process at once unless a shared external limiter is added.

Bare and native controls use one intervention call. Matched and Mini use expression, source-text-withheld reading and criticism. Native reasoning is an explicit provider setting. The shared prompt renderer makes direct matched and Mini conditional requests identical for the same prior public outputs; Mini's routed inputs must be checked before that rendering is admitted. This comparison checks routing and record behavior. It is not evidence for an invisible semantic advantage of a harness label.

The source packet port is absent from the reading stage. The selected language and actual expression remain visible and can carry source information. Prose escape is legitimate and can reproduce exact source text; attribute downstream recovery accordingly. No original proposal or candidate language is revised or installed during this block. Compiler observations, if present, are declared auxiliary inputs whose inclusion requires a new plan.

## Diagnose and continue

Inspect raw public responses, every sent request, Mini's original briefs and transformed request hashes, terminal results, errata and partial histories. An incomplete route must remain visible. Interpret source fragments and criticism independently of operational completion. Add substantive reviews under docs/reviews without editing published records. Follow the publication workflow immediately after each completed configuration.

A component intervention needs an actual component in the model's language, a proposed mechanism and an independently inspected exact difference. A later new-construction task must preserve the initial corpus while introducing a distinct successor artifact. Promotion of an unresolved criticism for investigation does not require pre-established bearing; attributing refutation or repair requires its further premises. Read RESEARCH_AGENDA for successor questions, and add new evidence to the appropriate lesson file rather than optimizing a scalar score.
