# Personal prose reasoning CLI

Paste a problem into a UTF-8 text file, choose cycles and a recipe, then run from `C:\Dev\miniReason`. This is a personal working tool. Its output is a working answer with its objections, not a finding. Offline delivery has exercised recording and routing with scripted responses; live usefulness remains to be inspected by the owner.

```powershell
$env:PYTHONUTF8='1'
$env:PYTHONPATH='src;tests'
$env:TMP='C:\tr12b'
& 'C:\Users\darre\AppData\Local\Programs\Python\Python311\python.exe' -c "from pathlib import Path; Path(r'C:\tr12b').mkdir(exist_ok=True)"
& 'C:\Users\darre\AppData\Local\Programs\Python\Python311\python.exe' tools/reason.py run --problem work/review12/smoke-problem.txt --cycles 2 --recipe cross-family --baseline --env-file .env --mode live
```

Supply keys through environment variables or opt in with `--env-file .env`. The repository-root `.env` is gitignored. Only `DEEPSEEK_API_KEY` and `OLLAMA_API_KEY` assignments are accepted; values are never logged or persisted. Loading happens before calls or run creation. The file and its resolved target must be inside this checkout, gitignored and untracked; tracked files are refused with `git ls-files --error-unmatch`. Blank lines, full-line comments and matching outer quotes are accepted. Values are literal without interpolation. Unknown names, duplicates, empty values and malformed assignments refuse the whole file before changing the environment. Default: no env-file read. `status` does not accept this option.

The first two smokes stopped at ceilings. Smoke-3 completed two cycles with 13 attempts (11 logical calls plus two schema repairs), `cycle_budget` and exit 0, and exposed the defects corrected here. It does not establish superiority. For plumbing without service calls, use `--mode offline`; offline is the default and its answers are labelled fixtures.

## Recipes

Shipped recipes set `closing_return: true`. This optional boolean allows one extra logical return after the final cycle if any use objection remains open. Custom recipes may set it false; omission defaults to false. Add up to one to the table below, plus two for `--baseline` when native control is available.

A recipe is a named, fixed composition. It is copied exactly into the run as `recipe.json`, and its SHA-256 appears in the run identifier and configuration. A custom JSON path is accepted by `--recipe`; supported schema and component paragraphs are illustrated by `src/minireason/reason/recipes/*.json`. The inventory cited by those recipes is retained in `work/w12/INVENTORY.md`, with complete source locations. That ignored engineering inventory is a local handoff artifact, not a published observation.

| Recipe | Seats and composition | Logical calls before baselines, repairs, retries or closing return |
|---|---|---|
| `single-family` | DeepSeek Flash conjecture, one critic and use; explicit return | `1 + 3 * cycles` |
| `cross-family` | DeepSeek Flash conjecture/return; Qwen3.5-397b and GLM5.3 critics; Qwen use | `1 + 4 * cycles` |
| `cross-family-rival` | Same cross-family composition, plus Kimi K3 alternative each cycle | `1 + 5 * cycles` |

Each seat is an object such as `{"endpoint": "deepseek-flash", "thinking": "native", "reasoning_effort": "medium"}`. Shipped loop seats and the native baseline declare `medium`; the baseline inherits the conjecture seat effort and the owner can raise it to `high`. Legacy seats without the field retain `high`. Effort is sent for native DeepSeek; Ollama, off and gateway-default payloads omit it through the unchanged provider builder. Thinking is `native`, `off` or `gateway-default`. All shipped direct DeepSeek seats use native thinking, including return, which reuses the conjecture seat. Shipped Ollama seats use the already-declared same-model .native endpoints at /api/chat with thinking off, sending top-level think:false through the existing transport extra field. Custom native Ollama seats send think:true and allow the same native-to-off fallback as direct DeepSeek. The /v1 routes remain gateway-default: a working off control there is NOT FOUND. The [recorded Kimi probes](../../tools/kimi_harness/PROBE-REASONING.md) found native think:false removed reasoning while /v1 ignored it; Smoke-3 recorded successful Qwen/GLM native calls with think:false and no native reasoning field; public content still included visible working. This establishes sent controls and recorded fields, not internal computation. Hidden native reasoning is discarded; public derivations are retained. Unsupported explicit gateway controls are refused.

CONJECTURE, BASELINE and RIVAL require an answer string. Optional assumptions and uncertainties strings or lists of strings are preserved in the parsed record and appended as labelled answer sections. This accepts the valid smoke-3 answer object without losing supplemental statements.

CONJECTURE makes a working prose answer available while holding the exact problem, named endpoint and declared resource settings fixed. Its original text remains inspectable after any revision.

CRITIC makes objections available, each naming what it would defeat. Critic, use and return may include an optional string `working` for visible working. Each objection `text` contains only the final objection statement, at most 1200 characters; a longer text raises `SCHEMA_FAILURE` with reason `OBJECTION_TEXT_TOO_LONG` for repair. Working stays in call records and CYCLE.md; it is excluded from objection delivery, TRACE.md and downstream prompt history. Bounds and field checks do not establish substantive validity. The cross-family recipes use different underlying lineages from the conjecturer. Two critic seats read the same answer independently, with prior objections, their dispositions, prior cycle history and the current rival when present. Each objection must name the exact step or claim challenged and evidence or a derivation that would show it wrong; merely requesting more caveats is forbidden. The single-family recipe deliberately keeps one lineage and does not supply that separation. After bounded repair/fallback, CEILING_HIT, TRANSPORT_OR_RESPONSE_ERROR or SCHEMA_FAILURE records critic unavailable: <code> for that seat. The cycle continues only if at least one critic returned a parsed objection list; if all fail, it stops with the last code. These arrangements are prospective compositions; the earlier record does not establish their general advantage.

RETURN in `public-working-v2` delivers every known objection with its exact ID, text and recorded disposition. Every new or still unresolved/open objection requires one disposition: `taken-up`, `rejected-with-reason`, or `unresolved`, with a nonempty reason. Earlier taken-up or rejected-with-reason objections need not be re-disposed; the engine carries their exact status and reason automatically and marks the per-cycle TRACE history `carried`. An explicit re-disposition of any known resolved ID is allowed and validated. Unknown IDs, duplicates, invalid statuses and missing required IDs fail with the offending IDs or fields named. Omitting a required disposition triggers one recorded schema-repair call, which receives the precise reason; a second invalid response stops that logical call as `SCHEMA_FAILURE`. These custody checks do not judge whether the criticism or response is sound.

USE poses a concrete question that depends on the working answer, derives its answer independently from the PROBLEM alone, then derives it separately from the WORKING ANSWER. The minimal response fields are `question`, `problem_derivation`, `working_derivation` and `objections`; both derivation strings include their conclusion. It must raise an objection if the conclusions disagree or the working answer cannot decide the question. The parser checks fields, not the truth or independence of either derivation. The use reader can be wrong. Its new objections remain unresolved until a later return. After the final budgeted cycle, closing_return runs one extra logical return if any use objection remains open, delivering all open objections for a final disposition. A reasoned unresolved disposition may remain open; acceptance is never forced. Success retains cycle_budget; a failed closing call records its actual stop code and preserves completed cycle evidence. A named ceiling, transport or schema failure after bounded recovery records use unavailable: <code>; the cycle completes without use objections. Unavailability is not a returned empty list. Arbitrary prose has no general external correctness oracle in this tool.

RIVAL, when selected, offers an alternative answer visible to criticism and return. The rest of the composition remains fixed. A rival is not an automatic decision about which answer the owner should accept.

STOP completes at `cycle_budget`, or earlier at `no_new_objections` when every critic has returned an empty list, the use seat returned an empty list, and no unresolved objection remains. An unavailable critic or use seat cannot trigger this early stop. These names describe the occurrence and its resource boundary. Silence is not a certificate of truth.

BASELINE with `--baseline` adds one bare call on the conjecturer and one with explicit native thinking if supported by the local adapter. Both receive only the original problem and the same answer instruction. Bare uses 8192 completion tokens; native uses 32768. Baselines remain first to preserve scheduling and minimize resume changes. In new runs, each baseline outcome is recorded in BASELINE.md and RUN.md; `CEILING_HIT`, `TRANSPORT_OR_RESPONSE_ERROR` and `SCHEMA_FAILURE` do not prevent the next baseline or loop from executing. Baselines have no ceiling fallback. The DeepSeek conjecturer supports both controls. Nothing is computed over the texts. The loop spends extra calls and tokens; this is not a matched multi-call experiment.

Keep a custom output root short.

Every attempt retains a 300-second wall. A wall stop is `TRANSPORT_OR_RESPONSE_ERROR`; a token-length stop is `CEILING_HIT`. An unterminated JSON container with reported completion usage at the request ceiling is also `CEILING_HIT`, even if finish_reason says stop; it follows the same existing native-to-off fallback. Unterminated JSON below the ceiling or with unknown usage stays `SCHEMA_FAILURE`, with its UTF-8 byte position recorded. Complete valid JSON at the ceiling is not by itself a failure. Input tokens are additional and grow with problem/history length. No transport retry occurs by default. If explicitly supplied, `--retry-transport N` permits up to N additional attempts per logical call for the named transport error, each with its own files and call count. A terminated remote request may still have incurred provider usage; unknown usage remains unknown. Fences and surrounding prose are tolerated by extracting the first top-level JSON object; new contracts also tolerate raw control characters in strings using strict=False. In `public-working-v2`, extra top-level keys (including `type: json_object`) are accepted only after all required fields validate. Their values remain in the parsed public record and their names appear in outcome `extra_keys`, TRACE and RUN; nested disposition/objection field sets remain exact. The actual bare-baseline smoke failure was valid JSON with extra assumptions/uncertainties fields. A valid earlier object in prose, such as an empty-set notation, still prevents choosing a later object opportunistically. A schema-invalid public output permits exactly one repair call for that logical call, in a new attempt directory: the model receives its own public output, named schema failure, and the same contract, endpoint, thinking setting and ceiling. It must faithfully convert its prior output, preserve final concrete objections and conclusions, move exploration into working, and avoid solving afresh. A second schema failure ends that logical call as `SCHEMA_FAILURE`; optional critic/use seats follow the unavailable-seat rules above. A failed repair is never transport-retried.

In new runs, a native loop seat (conjecture, return, rival, critic or use) that hits `CEILING_HIT` permits exactly one fallback attempt in the next `aNN` directory, with thinking `off`, the same current messages and the same selected native ceiling (32768 in shipped recipes). This exception keeps 32768 for the fallback rather than applying the normal off ceiling. It may follow a native schema repair that hits the ceiling. The call outcome declares the decision; the fallback request/outcome, TRACE.md and RUN.md record it explicitly. A fallback failure ends that logical call with its actual status: a second ceiling stop remains `CEILING_HIT`. Conjecture/return/rival failures are fatal; named critic/use failures follow the unavailable-seat rules. Fallbacks receive no further schema repair or transport retry. Off and gateway-default seats have no ceiling fallback; their failures follow the same role-specific fatal/unavailable rules. Saved indeterminate attempts are never silently replayed.

With L planned logical calls including the conditional closing-return allowance, K native loop calls and N configured transport retries, maximum attempts are L * (2 + N) + K. Let S be the sum of their completion ceilings and T the sum for native loop calls; maximum completion allowance is S * (2 + N) + T. Cross-family, two cycles and baselines has 11 scheduled logical calls plus up to one closing return: L=12, K=4. With no retries the allowance is 28 attempts and 573440 completion tokens; without recovery the allowance is 221184. Disabling closing_return restores 11/25 attempts and 188416/475136 completion allowances. At 300 seconds per attempt, 28 attempts allow up to 140 minutes of provider-attempt wall time, plus orchestration overhead. These are limits, not predictions or a matched comparison.

Missing prompt_contract uses exact legacy contracts, strict parser and old repair wording; missing closing_return adds no final call. Frozen recipes are never upgraded on resume. It can continue after an interruption between completed calls, including when the provider response was saved before the outer recorder finished. A request whose delivery outcome is unknown stops as `INTERRUPTED_CALL` rather than replaying it. Resolve that evidence manually; if a fresh attempt is desired, create a separately identified new run. Simultaneous writers are refused as `RUN_BUSY`. ## R002 strict instruments

R002 has separate `run-r002` and `run-r002-native` commands. The legacy `run` behavior above is unchanged. The published draft under `experiments/diagnostics/R002-episodes-under-calibrated-difficulty/` remains frozen input; its recipes retain their historical `PROPOSED_NOT_SHIPPED` label. The successor implementation validates their exact pinned bytes rather than rewriting that observation. `tools/run_R002.py` is the engineering launcher; the experiment directory's original launcher remains its published draft.

R002 uses `r002-episodes-v2`, exactly one attempt per slot, at most three cycles, 16384 completion tokens for off seats and 32768 for native seats, and a 300-second provider wall. On Windows the strict worker is owned by a single-process kill-on-close Job Object; `provider/supervision.json` retains actual elapsed time, requested wall, termination backend, exit status and any wall breach. There is no schema repair, native fallback or transport retry. A failed critic is a censored occurrence, never an empty objection list or evidence of blindness. Every role permits `cannot_decide` with a named missing derivation. Public working is limited by the frozen schemas, including 6000 characters and at most three critic objections. Every participant request includes its exact frozen role schema and transitive local schema dependencies. The use seats receive the same public candidate ID, checker eligibility and oracle-kind discriminator; sealed oracle material is excluded.

All answer roles number public derivation steps. Objections bind an exact earliest challenged step quote, index and public branch ID. CROSS requires the fork but allows prose objections without a check; TESTED requires a finite check and its redo before acceptance or rejection. Taken-up objections reconstruct the derivation from the fork forward. The host detects literal tail edits, including changed conclusions with wholly copied derivations, and records them as reading evidence; it cannot judge the earliest substantive error or whether a changed derivation is sound. Known resolved dispositions carry forward. An unredone check remains unresolved.

RECODED uses two blind solves by the same DeepSeek lineage on the canonical and frozen branch-recoded problem. The map preserves declared relation IDs and canonical output values. The optional CARRIER companion substitutes a declared irrelevant carrier disturbance. There is no extra recoder model call in the judged schedule. Public branches and frozen transformations supply the recoding; sealed answers, oracle output, working answers and prior objections never enter blind requests. A mapped disagreement becomes a fork-bound objection without identifying a correct side; absent derivations remain unresolved evidence.

Every loop can stop at no-new-objections only when no open objection remains, and makes one closing return after its last completed cycle. After two unchanged transitions in complete type-preserving decisive relation maps, an open objection triggers a `stall switch` before cycle three. CROSS/TESTED/CHECKER replace their two signal slots with same-lineage recoded/carrier solves; RECODED/CARRIER replace them with Qwen/GLM tested critics. The selected target is lowest fork index then immutable ID. No cycle or call is added. Missing relation values mean `stall_unknown`. Switches are reading strata, not quality judgements.

Computable use seats propose the same deterministic Python check in every loop. Only CHECKER executes it; the other arms archive the proposal. Execution records retain code, explicit stdin, output, exit status, elapsed time, runtime/policy identity and comparisons. A mismatch becomes an objection the return must redo; it does not certify the checker or identify truth. Derivation-only tasks have no checker. The independent review reproduced and repaired a profiler/frame escape, then reran the hostile battery. Under the owner's explicit review standard, LOOP-CHECKER is runnable on this host with the following declared limits.

The AST allowlist permits only collections, decimal, fractions, functools, itertools, json, math, operator, statistics and sys, rejects filesystem/process/network/dynamic-import/reflection access, and is reinforced by runtime import/open/audit guards, including socket, profiler/frame and os mutation denial. Main reruns archive the prior failed directory byte-for-byte and allocate a distinct attempt identity. A write-once base phase receipt is preserved; later reruns produce numbered phase supplements. Child stdout/stderr are retained separately. A live admission requires all24 exact trial identities, public answer paths/hashes or explicit absence, task/answer/oracle pins, reading UTC, quoted claims/derivation references and a declared distinct reader lineage. The instrument checks those declarations and hashes; the guarded reader and publisher establish the reader's actual identity and independence.

Episode files live under `episodes/<objection-id>/`: one immutable record per return disposition, plus a separately named later-use supplement when available. A closing-only disposition has `closed_without_propagation`; no later use is invented. An answered later-use artifact yields only `slot_chain_present`, while a cannot-decide use yields `incomplete`. The original public calls remain the primary evidence. Tests use `MINIREASON_TEST_WORK` for persistent fixtures; review20 uses `work/review20/tests`. Earlier worker fixtures remain below `work/w20`; the checker child's empty work directory is temporary. W20's offline validation is appended to the frozen study's VALIDATION.md, with full transcripts and the future detached calibration command indexed under `work/w20/INDEX.md`.
