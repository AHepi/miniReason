# Continue the inquiry

Read PURPOSE and STATUS first. Verify the remote `main` identity, the local branch and all uncommitted files before claiming that prior work is published. Preserve unexpected user changes. Read the latest experiment plan, the complete unsuccessful records as well as successful ones, and the relevant errata and lesson files.

Reconstruct which configurations actually ran. A directory, a compiled manifest, a provider smoke check or a mocked response is not a completed model comparison. Verify the call records and Mini log, the final checker evidence and whether the record contains an interruption. Treat runs lacking a terminal record as interrupted, never as negative task results.

Choose the next experiment because an identified mechanism remains unresolved. State what differs from its parent, what should happen if the diagnosis is right, what would defeat it and which control shares the new information and call allowance. Freeze the original task, template and checker identities before sending. Keep model prompts isolated between concurrent configurations. At most five configurations may run at once.

Run offline checks before spending tokens. Load the authorised DeepSeek credential only into the process environment. Keep credentials out of shell output and repository content. Follow [experiment](experiment.md), then [publish](publish.md) immediately after the test finishes.

When there is a blocker, name it precisely and preserve reviewable work. When stopping by judgement, state the failed and surviving mechanisms and why each plausible next intervention is unlikely to resolve the current question. A finite campaign never literally exhausts every possible configuration.
