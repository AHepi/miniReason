## 3. Occurrence, conditions and actual readiness

An **occurrence** is one numbered, frozen matrix of selected problems and conditions. Default: all eight problems and the three conditions below, 24 CLI runs. For a lighter first occurrence, select O01 explicitly: three runs. A cell is one problem/condition run, and an episode is a content-linked target/criticism/response history inside that run. These are not interchangeable units. Each new occurrence has a one-sentence question before dispatch. For example: "On O01, does criticism produce a specific usable reframing missing from fresh native reasoning?"

| Condition | Requested target |
|---|---|

| LOOP-CROSS | HEAD-published R002 `r002-cross-v2` seat arrangement: DeepSeek native initial/return, independent Qwen3.5-397b.native and GLM-5.3.native critics with thinking off, DeepSeek off use. All arms receive the same exact problem and no reader brief or prior-condition answer. Common answer formatting is an enabling instrument and must be disclosed when calling NATIVE a direct baseline. Native hidden reasoning is not available for reading; only public answers/derivations and reported counts are retained. A2 repair means faithful formatting of the same public answer on the same seat, thinking and allowance, not fresh solving. Preserve both attempts; stop on the second schema failure. CEILING_HIT and transport failure stop without retry or native-to-off fallback. Input overflow stops before send, with no truncation. Public JSON checks establish delivery only.

CROSS's closing return disposes the still-open use objections after the last cycle. A2's existing synthesis is not a closing return: it only runs after every planned step is accepted. It may produce a revised final answer or explicit suspension; it cannot rewrite accepted-step records, mark a disputed old step accepted, or claim subsequent use. Fatal instrument/resource failures still terminate before closure. Longer-than-three-step plans remain partial, even if a closing response explains that limitation.
