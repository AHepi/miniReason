## Exact set of availability values

Availability = capacity − sum of reservations over an admissible combination (R6).

Sum = effect(A) + effect(B) + effect(C).

- effect(A) = 0.
- effect(C) = 0.
- effect(B) ∈ {3, 8}.

Admissible sums: 0 + 3 + 0 = 3, and 0 + 8 + 0 = 8.

Combinations: capacity 6 minus 3 → 3; capacity 6 minus 8 → −2.

**Exact set of availability values: {3, −2}.**

Duplicate ways of obtaining a value do not create a different value (R6).

## Remaining problem

One problem remains live and is not resolved by producing the correct answer: the **bounds versus set** distinction is fragile under repetition. The interval [−2, 3] here happens to have the exact set {3, −2} as its extremal endpoints, so a downstream calculation that consumes only lower and upper will sometimes coincide with the exact set and sometimes not — and coincidence, not correctness, will be doing the work. A projection that reports only bounds is lossy in exactly the sense RSS warns about; the contract's R6 catches the specific equating but does not prevent a consumer from using the bounds as if they were the set whenever the endpoints match. Nothing in the contract or RSS supplies a further check for this. This is a limit of the representation in use, not a defect of this snapshot, and I carry it forward rather than resolve it here.
