## Fresh case D: the operative computation

Rules in force: R2 (payload identity vs. delivery provenance), R3 (greatest revision selected from *all* delivered payloads before any effect is considered), R4 (release reserves zero regardless of its other fields; hold reserves quantity strictly when current time < expiry, and zero at equality or later; expiry changes effect, not authority), R5 (one payload alternative per booking at its greatest revision; different bookings independently admissible; no cross-booking constraint supplied), R6 (availability = capacity − sum of reservations; exact set reported as a set; bounds separate; a covering interval must not be equated with the exact set unless all intervening admitted integer values occur; negative availability permitted).

Capacity 8, current time 7.

**Booking A.** Delivered payloads: a1 (rev 1, hold, qty 6, exp 20); a3h (rev 3, hold, qty 2, exp 7); a3r (rev 3, release, qty 9, exp 99). Greatest revision is 3. a1 is superseded before any effect is considered (R3), regardless of the expiry or kind of the rev-3 payloads. At rev 3 there are two distinct payloads: a3h and a3r; neither is an exact repeat of the other, so both are live alternatives (R5).

Effects at t = 7 (R4):
- a3h: hold, and current time equals expiry (7 = 7), so it is expired; effect 0. It remains the authoritative rev-3 record; its zero effect does not revive a1.
- a3r: release, so effect 0 regardless of quantity 9 and expiry 99.

Booking A contributes the set {0}. The interesting point is that *both* rev-3 alternatives yield 0 here, by different routes: a3h because equality is treated as expired (R4's "strictly less than expiry" condition), a3r because a release reserves zero regardless of any field. So the alternative structure at A collapses, at this time, to a single achievable contribution, but not by supersession — by the coincidence that both effects are 0.

**Booking B.** Delivered payloads: b2a (rev 2, hold, qty 2, exp 10); b2b (rev 2, hold, qty 5, exp 10); b2b-copy (rev 2, hold, qty 5, exp 10). Greatest revision is 2. b2b and b2b-copy have identical payloads in all five record fields; b2b-copy is an exact repeated payload and conveys no additional authority (R2). It is inert, not a confirming second witness. At rev 2 the distinct payloads are b2a (qty 2) and b2b (qty 5). Both are alive at t = 7 (7 < 10), so their effects are, respectively, 2 and 5. Booking B contributes {2, 5}. The arriving delivery labels differ, but R2 says payload identity, not delivery provenance, is the question of authority; the label is an occurrence marker only.

**Booking C.** Delivered payloads: c2 (rev 2, release, qty 0, exp 0); c1 (rev 1, hold, qty 7, exp 20). Greatest revision is 2. c1 is superseded before effect (R3), even though c2 is a release whose quantity and expiry look inert. That is exactly R3's clause "a lower-revision release does not cancel a higher-revision hold" running in the *other* direction than it is often invoked: here a higher-revision release supersedes a lower-revision hold; the lower hold does not remain effective merely because the superseding record is a release. c2 reserves zero (R4). Booking C contributes {0}.

**Availability set.** Capacity 8. Sums of independent choices: A contributes only 0; B is 2 or 5; C contributes only 0. Admissible sums: 0 + 2 + 0 = 2 → 8 − 2 = 6; and 0 + 5 + 0 = 5 → 8 − 5 = 3. Exact achievable availability set: **{6, 3}** — two values, ordered by reservation.

**Bounds, reported separately (R6).** Per booking: A lower = upper = 0; B lower = 2, upper = 5; C lower = upper = 0. With capacity 8, the maximal availability corresponds to minimal reservation and equals 8 − (0 + 2 + 0) = 6; the minimal availability corresponds to maximal reservation and equals 8 − (0 + 5 + 0) = 3. So the bounds are 3 and 6. Reporting [3, 6] as a covering interval is permitted, but it must not be equated with the exact set {3, 6}: the intervening integers 4 and 5 do not occur, because B admits only a reservation of 2 or 5 — never 3 or 4 — and A and C admit only 0. This is the same point the earlier response made for case A against Memo A2: replacing two points by the covering interval silently imports reservations that no admissible combination yields.

**A note on which clauses are not exercised by case D.** R3's specific clause on a lower-revision release not cancelling a higher-revision hold is *cited* by C's shape but is not the operative clause there: in C, the higher record is itself the release, so what matters is that a higher-revision release supersedes a lower-revision hold and reserves zero. The clause would be operative if, for instance, a booking carried a rev-3 hold and a rev-1 release; case D has no such booking. I mark this so that "case D illustrates R3's release clause" is not claimed beyond the evidence.

## Discrepancies between the specimens and the contract

Neither specimen is the contract, and each diverges from it in ways case D makes concrete.

- **WHL** offers `reserves_effect` (retained-expiry reading) and `expired_deletes_rule` (deletion reading) and "does not choose between them." The contract does choose — R3/R4 fix retained-expiry-with-structural-supersession. Under the deletion reading, a3h at A in case D is deleted, a3r would then be alone at rev 3, and a1 would still be superseded by a3r's rev 3 (since a3r remains at rev 3), so A's contribution is still {0} *in this particular case* — but for a case where the sole rev-3 record is an expired hold with only lower-revision payloads remaining, the two readings differ (deletion would revive the lower revision). Case A is such a case: under deletion, a2 would be removed and a1 would then be at rev 1 with no higher revision present, effect 8, and A's contribution would be {8}, changing the availability set. So the deletion-vs-retained choice is not merely conceptual; it is observable across the two cases.
- **WHL `possible_reservations`** returns a list, and the specimen declines to declare bag equality. The contract's R6 speaks of the exact *set*. On these cases the set and list coincide with respect to values, but the representational difference matters if payloads were to produce equal effect quantities under distinct alternatives — the list would carry duplicates the set would collapse. Neither case D nor case A produces such a collision among *distinct* payloads, but the divergence is real and is not smoothed away.
- **WHL's** treatment of `greatest_revision_in` uses `dominated_in` on a list, and its text does not by itself specify *when* the authority decision interacts with expiry. The contract's R3 fixes the order (greatest revision first, on all delivered payloads, before effect). The specimen is compatible with the contract's order but does not enforce it.
- **RSS** treats the snapshot as a *viewpoint* and does not decide between expiry readings; it "records the disagreement." The contract takes one reading (R4). RSS also treats the delivery label as *provenance* — its `Story` primitive carries provenance — and says exact duplicates (which for RSS include provenance) add no authority. R2 is *sharper*: exact repeated *payloads* convey no authority regardless of delivery labels. Case D exercises precisely this: b2b and b2b-copy differ in delivery label; RSS's "exact duplication" (which includes provenance) would not call them exact duplicates, whereas R2 treats the payload repetition as inert. So the contract's rule and RSS's exact-duplication are not the same rule, and case D exposes the difference.
- **R3's release clause** ("a lower-revision release does not cancel a higher-revision hold") is stated flatly in the contract; WHL reaches zero effect for releases via `reserves_effect`, but does not make the authority-blocking claim; RSS lists both readings as *readings* rather than committing. The contract commits.
