## 1. The operative contract, stated once

Before computing I fix which rules operate, because the cases turn on them and because R1 and R4 contain a real divergence from the original WHL text.

- **R2.** Exact repeated record payloads (all five fields equal) convey no additional authority, even when delivery labels differ. Different payloads at the same greatest revision are alternatives.
- **R3.** Greatest revision is selected from all delivered payloads *before* considering effect. A lower revision remains superseded even when the greatest-revision hold has expired. A lower-revision release does not cancel a higher-revision hold.
- **R4.** A release reserves zero regardless of other fields. A hold reserves its quantity exactly when current time is strictly less than expiry; at equality or later it reserves zero.
- **R5.** One payload alternative is selected per booking at its greatest revision; alternatives of different bookings are independently admissible; no further cross-booking constraint or preference is supplied.
- **R6.** Each admissible combination gives availability = capacity − sum of bookings' reservations. The exact set of attainable values is reported when asked. Bounds may be reported but must not be equated with the exact set unless every intervening admitted integer value occurs. Negative availability is permitted.

**Discrepancy exposed (R1, carried from earlier work; re-derived here from the supplied texts).** The original WHL specimen defines

```
def reserves_effect (t : Time) (r : Record) : Quantity :=
  match r.kind with
  | Kind.hold => if t > r.expiry then 0 else r.quantity
  | Kind.release => 0
```

which returns `r.quantity` at `t = r.expiry`. Contract R4 second sentence says a hold reserves its quantity exactly when `t < expiry`, and "at equality or later it reserves zero." These disagree at the single point `t = expiry`. I do not smooth this over and I do not edit either text. R4 is the operative contract for this task, so where equality occurs I apply R4 (zero at equality). I record where the two agree and where they would diverge, per case, below. The earlier occurrence of this observation is retained-not-re-presented as an anchor; I re-derived it here from the two supplied texts themselves, so it does not depend on recall.

### 2.4 Exact availability set for case D

Per R5, one alternative is selected per booking, independently across bookings; per R6, availability = capacity − sum.

Admissible choices: A ∈ {0}, B ∈ {2, 5}, C ∈ {0}.

- (A=0, B=2, C=0): sum 2, availability 8 − 2 = **6**.
- (A=0, B=5, C=0): sum 5, availability 8 − 5 = **3**.

**Exact set of availability values: {6, 3}.**

**Separate bounds (WHL `availability_lower_bound` / `availability_upper_bound`, per-booking min/max of `possible_reservations`):** sum of per-booking minima = 0 + 2 + 0 = 2; sum of per-booking maxima = 0 + 5 + 0 = 5; lower availability bound = 8 − 5 = **3**; upper availability bound = 8 − 2 = **6**. In display order the interval is [3, 6]. Here the attainable set {6, 3} *coincides* with the bound endpoints, and — because the only multiplicity is a two-element set in a single booking — there is no strictly interior integer in [3, 6] that is admitted but unattained: the only integers strictly between 3 and 6 are 4 and 5, and 4 is not an admissible sum (2 + 2 = 4 is not available since A and C contribute 0 and B contributes 2 or 5). So 4 is unattained. This is the interior-filling situation in miniature: bounds [3, 6] contain 4, which no admissible combination produces, so even here the bound interval is not the exact set. The exact set is {3, 6}, not [3, 6]. R6's "must not be equated… unless all intervening admitted integer values occur" is satisfied only if 4 occurred; it does not, so the equality is denied.

The `b2b-copy` delivery is the R2 lesson made concrete: two delivery labels (`b2b`, `b2b-copy`) carry one payload and confer no extra authority, so B's lower alternative is 2, not something weighted by label count. If label count were authority, B's alternatives might be treated as three with a duplication boost, which R2 forbids and which the WHL `alternatives_at_greatest` relation blocks by excluding exact duplicates.

## 4. Discrepancies between the original WHL representation and the contract

**Exposed divergence (not silently repaired).** As in §1: WHL `reserves_effect` returns a hold's quantity at `t = expiry` (`if t > expiry then 0 else quantity`), while R4 says zero at equality ("strictly less than expiry"). Case D booking A is the one place in these two cases where this bites: `a3h` has expiry 7 and the case time is 7, so under WHL's own function A's possible reservations would include 2, and case D's exact availability set would become {6, 8} (B=5 → 8 − 5 = 3 was 3; with A=2 the sums become 2+2=4 and 2+5=7, giving availabilities 4 and 1, so the whole set changes). I apply R4 (operative) and get {6, 3}; I record that WHL's coded rule would give a different case-D set, so the divergence is material here, not decorative. In case A and in case D's B and C bookings the two rules agree, so case A is unaffected.

**Alignment (no discrepancy).**
- R2 with WHL `exact_duplicate` / `alternatives_at_greatest` (case D `b2b-copy`; case A `b1-copy`).
- R3 with WHL `greatest_revision_in` consulting only booking and `revision_lt` (both cases; expiry not consulted in selection). WHL's definitions are silent on expiry within selection; it is R3 that supplies the exclusion of dominated lower revisions even when the greatest-revision hold is expired.
- R4 first sentence ("release reserves zero") with WHL `reserves_effect` for `Kind.release` (both cases' C bookings).
- R6 ("negative availability permitted") with WHL's `Int` / `Int.sub_nat` (case A's −2).

**Sharpening where the contract exceeds WHL's own text.**
- R5's cross-booking independence is what WHL's own notes flag as an expressive limitation ("the language cannot express incompatibility between alternatives of different bookings except through the capacity sum"). R5 supplies that independence; case D's {6, 3} and case A's {3, −2} are computed as independent per-booking selections, which is R5's doing, not WHL's.
- R6's "must not be equated with an exact set unless all intervening admitted integer values occur" is a discipline WHL's bound functions do not themselves state. WHL computes `availability_lower_bound` / `availability_upper_bound`; it does not forbid substituting the interval for the set. Case A (interior values −1, 0, 1, 2) and case D (interior 4) are live instances where the prohibition is load-bearing. I attribute the prohibition to R6.
