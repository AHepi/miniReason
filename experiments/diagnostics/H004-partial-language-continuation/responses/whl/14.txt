## 3. Memo C clause by clause, now assessed directly with the template available

The block asks that I "distinguish a defect in a proposed language clause from a defect in an individual application." I do this explicitly, using the template: for each clause, (i) does the selected representation or the rival actually state the rule the clause attributes to "the representation"? (ii) if not, is the clause's content an *absent distinction* (a limitation) that the representation can even *state its inability to state*? (iii) is the residual observation usable at the application level?

### C1 — assumption-rejection as refutation

Rule attributed to the representation: rejection of a supporting assumption *is* a refutation; therefore A's conclusion is established false *for every account*.

Clause check, WHL: `Refutation c := (snap : Snapshot) (not_c : ¬ c snap)` — a counterexample refutation of one conjecture. WHL's own note: "Source assumptions are not primitive. The language can state them as conjectures or commitments, but it does not encode a notion of assumption dependence." So WHL does not state C1's rule; WHL *cannot state* it, and WHL *says* it cannot. That is the "limitation stated as a limitation" form: WHL doesn't endorse the conflation and doesn't flinch from stating that it is silent on it.

Clause check, RSS: RSS *does* list type (c) refutation ("a demonstration that a conjecture depends on an assumption that another account rejects"), and RSS *scopes* it as local ("Refutations are local to accounts and do not force global agreement"). So one half of C1's rule is available under RSS, and the other half — "for every account" — is contradicted by RSS's own text.

Outcome: C1 as a **criticism of a language clause** is invalid. C1 as a **criticism of an application** would be valid against an application that globalised assumption-rejection; no such application is supplied, and I will not manufacture one. The *underlying observation* (WHL cannot express assumption-dependence) is a real, self-declared limitation. Cycle 11's C1 verdict is retained. Cycle 12's C1 refinement ("WHL's *silence* is not a conflation it *makes*") is retained and is what the template now states uniformly. Cycle 13's C1 status in its table ("invalid as clause-level criticism; valid as application-level only if supplied") is retained.

### C2 — local commitment closing global inquiry

Rule attributed: one account's commitment closes the question for every account.

Clause check, WHL: none. WHL has no inquiry-state primitive; `Commitment : Type := Prop` carries no globalising machinery. The *absence* is total — WHL has nowhere for the rule to live.

Clause check, RSS: RSS has an inquiry-state primitive, and it is *designed* so no account's commitment closes the question for another ("Commitment is local to an account"; a conjecture is "open if no account has committed to it or refuted it"). RSS rejects the rule by construction.

Contract check, R7: "Rejection of one supporting assumption can defeat that support route without proving its conclusion false."

Outcome: same template as C1. RSS expresses the constraint by *explicit primitive* and *rejects* C2's rule; WHL expresses the constraint by *no primitive at all*, so there is nothing to reject and nothing to assert. C2 is a **strawman at the clause level in both languages**. Cycle 11's verdict retained. Cycle 12 retained it without change. Cycle 13's §5 template now explains *why* it is a strawman in each language rather than only *that* it is — a gain, but a gain of formulation, not of verdict.

### C3 — every projection must lose information

Rule attributed: projections are always lossy, including on a singleton domain and for injective projections.

Clause check against the *selected* representation WHL: the WHL specimen does not state a projection-always-lossy rule. WHL's treatment of representational loss is R6's: "An interval may be reported as bounds but must not be equated with an exact set unless all intervening admitted integer values occur." That is a *typed* discipline: the exact-set report and the bounds report are distinguished, and equating them when interior values are unattained is the error. WHL is thus a representation in which the lossy/non-lossy distinction is *load-bearing* and *typed*.

Clause check against the *rival* RSS: RSS states the slogan — a projection is "a function from a viewpoint and a reading to a single answer … always a loss of information." RSS does not qualify it.

Outcome: C3 as a criticism *of WHL* is invalid; WHL does not state the slogan. C3 as a criticism *of RSS's slogan* is valid, but the target is RSS. C3 as an *appraisal rule* ("representation must therefore be defective") is invalid; the singleton and injective cases refute the universal form. Residual usable content, at the application level: R6's typed discipline, with concrete instances {3, −2} vs [−2, 3] and {5, 1} vs [1, 5] showing endpoint-agreement without exact correspondence. Cycle 11's "half-sound, half-defective, mis-targeted" verdict is retained, and its mis-targeting is now grounded in R6's typed discipline rather than in a claim about RSS's tone. That grounding is a cycle-12 contribution.

I revise one thing from cycle 12. Cycle 12 said R6 "encodes a *typed* distinction … whereas RSS's slogan collapses both cases into 'always lossy,'" implying RSS's slogan is *not* load-bearing in RSS. I now hold that more carefully: RSS's slogan is a *secondary rhetorical claim* in RSS, not a primitive. RSS's primitives list is Story, Bag, Coordinate, Viewpoint, Conflict, Liveness, Reading, Projection. The "always a loss of information" sentence appears in the primitives list for Projection, so it is not fully detachable from RSS's self-description — it is a *primitive-level remark* that overstates a real point. I do not say RSS's slogan is "not load-bearing"; I say it is an overstatement *within* a primitive's description, and the correct repair, if one were proposed, would be to qualify it (e.g. "lossy when non-injective on the admitted domain"). That qualification is a *proposed extension* on RSS, attributed as such; I do not attribute it to the original text.

### C4 — no algorithm supplied ⟹ noncomputable

Rule attributed: an omission in a semantic proposal *proves* the represented problem noncomputable.

Clause check against WHL: WHL's per-booking selection is finite-domain enumeration. `possible_reservations` filters a finite list, computes `greatest_revision_in` on finite sets, and maps `reserves_effect` over the result. `availability_lower_bound`/`availability_upper_bound` fold over finite booking lists. Nothing in WHL's own admitted domain is noncomputable. So C4's conclusion, if it were true for some *general* warehouse problem, would not reach WHL's per-booking task.

Clause check against RSS: RSS *declares* "It is deliberately noncomputable." That declaration is a *design property of the semantic class*, not a theorem about the underlying problem. RSS does not provide a reduction, a diagonal argument, or a theorem. So RSS *states* noncomputability of the class, and *does not* state noncomputability of the underlying question.

Outcome: C4 is a **presentation/decidability collapse** at the clause level and at the inference level. Cycle 11's "category error" verdict is retained; cycle 12's "unwarranted disjunction collapse" is retained as the sharper diagnosis; cycle 13's status ("invalid inference; irrelevant to WHL's finite per-booking enumeration") is retained. One thing I add here, attributed to this response: the collapse is *not* symmetric in a way that favours C4 either. "Presentation with no algorithm supplied" is compatible with both "underlying function computable" and "underlying function noncomputable," so C4 does not even have a default inference available. It has an *undetermined* target.

### C5 — existence of a Lean predicate proves faithfulness and adequacy

Rule attributed: type-existence is semantic authority, and it certifies both faithful naming and adequate application.

Clause check against WHL: WHL *explicitly separates* type from intended meaning. `exact_duplicate` is defined by a structural conjunction; the notes state that this "is represented by `exact_duplicate`: two records with all five fields equal are inert with respect to each other. The language does not say that near-duplicates are inert; they may be alternatives." The notes state that the language "does not assert which conjectures are true; it provides the vocabulary to state them." The notes state, as *expressive limitations*, that source assumptions, replication, physical resource sharing beyond capacity, and per-replica logical time are not primitive.

Outcome: C5 as a **universal appraisal rule** is invalid. If adopted, it would classify WHL's explicit type/meaning gap — the file's own stated design feature — as an error. Cycle 11's "existence ≠ faithfulness" verdict is retained; cycle 12's sharpening ("C5 would *require WHL to be worse than it is designed to be*") is retained; cycle 13's same verdict is retained. The residual at the application level — a particular *use* of a predicate can be criticized case by case — is where application-level criticisms of naming or adequacy legitimately live.

### C6 — expressibility of false claims is not a defect; the question includes what distinctions the representation allows us to inspect, criticize and use

Outcome: **valid and adopted**. C6 is the register statement; it is also what memo C's own construction *enacts*. Cycle 11, cycle 12 and cycle 13 all adopted it. I retain.
