## Exact set of availability values

Availability = capacity − sum of reservations over an admissible combination (R6). Capacity = 8.

Sum = effect(A) + effect(B) + effect(C).

- effect(A) = 0 (either alternative).
- effect(C) = 0.
- effect(B) ∈ {2, 5}.

Admissible sums: 0 + 2 + 0 = 2, and 0 + 5 + 0 = 5.

Availability values: 8 − 2 = **6**; 8 − 5 = **3**.

## Remaining problem, identified but not settled

One problem is warranted, and I carry it forward rather than resolve it.

The bounds-versus-set distinction is fragile under exactly the situations case A and case D exhibit. In both, the exact availability set is the pair of endpoints of the bounds interval — {3, −2} with bounds [−2, 3] in case A; {6, 3} with bounds [3, 6] in case D. A downstream consumer that reads only lower and upper will *coincidentally* recover the same two numbers every time the set is a two-element symmetric pair, and *fail* when the set is not (a three-alternative booking, a zero-width set, a capacity that produces interior values). Coincidence, not correctness, would be doing the work in the matching cases. RSS's own class-level slogan that "a projection is always a loss of information" describes exactly this: reporting only bounds is a projection of the exact set. R6 catches the specific equating, and the block's instruction to "separate bounds" catches it for these cases, but neither supplies a check that survives the endpoint-matching coincidence. This is a *representational* limitation of the use policy, not a defect of case A or case D, and not a new defect in Memo D. I do not manufacture a fix.

A second remaining problem I mark but do not diagnose: in case D, booking A's greatest-revision conflict is a hold/release pair whose two alternatives happen to reserve the same value (zero, for different reasons). Whether such a coincident-value conflict should count as "resolved" for downstream purposes is a question RSS leaves open — RSS records disagreement, it does not rank resolutions — and the contract's R5 says each booking selects one alternative without prescribing on coincident-value collapse. R6 says duplicate ways of obtaining a value do not create a different value; it does not decide whether two different-mechanism alternatives yielding zero are "the same resolution" or "two resolutions with the same output." This remains open.
