## Exact set of availability values

Availability = capacity − sum of reservations over an admissible combination (R6). Capacity = 10. Sum = effect(U) + effect(V) + effect(W) = 0 + 3 + effect(W).

- effect(W) = 2 → total 5 → availability 10 − 5 = 5.
- effect(W) = 6 → total 9 → availability 10 − 9 = 1.

Duplicate ways of obtaining a value do not create a different value. Note that w1 and w1-copy give the same reservation, so the "2" is obtained by either label but counts once.

**Exact set of availability values: {5, 1}.**

## Separate bounds

Per-booking lower/upper bound = min/max of possible reservations, 0 if none: U lower 0 upper 0; V lower 3 upper 3; W lower 2 upper 6. Sum of lower bounds = 0 + 3 + 2 = 5 → lower availability bound = 10 − 5 = 5. Sum of upper bounds = 0 + 3 + 6 = 9 → upper availability bound = 10 − 9 = 1.

**Bounds: [1, 5].**

Here the bounds coincide with the exact set as its endpoints — but only *here*. The interval [1, 5] contains 2, 3, 4, which are not in the exact set {5, 1}. So bounds ≠ set in this snapshot too; the endpoints merely happen to be the extremal values of the set. R6 permits reporting the interval as bounds but forbids equating it with the set. Reporting [1, 5] as if it were the set would admit availability values (and hence scheduling decisions) that no admissible combination produces — exactly the loss RSS names for a projection.

## Remaining problem

The live, unresolved problem is B6(a)'s **scope question**: coupling between bookings' alternatives. Both supplied cases have no cross-booking selection constraint (R5), so the exact sets are simply the sums of per-booking alternatives. But nothing in RSS, in WHL, or in R1–R8 supplies a coupling/resource model, so we cannot investigate what availability values a physically-constrained warehouse would produce without manufacturing a policy. What would have to be supplied to investigate it without manufacturing a policy is at least: (i) a resource model primitive declaring which combinations of alternatives of different bookings are jointly feasible; (ii) a reading of how a coupling constraint interacts with capacity (does capacity remain the only global sum, or do alternatives of different bookings compete for a shared resource?); (iii) a way to state the coupling inside the representation, since RSS's stories and WHL's filtered lists carry no cross-booking constraint. Absent these, the scope question is carried forward, and the old R5 result stands as a conditional claim whose applicability is suspended.
