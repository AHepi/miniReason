## Exact set of availability values (R6)

Availability = capacity − (effect(A) + effect(B)), capacity = 3.

Admissible sums and results:

| A effect | B effect | sum | availability = 3 − sum |
|---|---|---|---|
| 1 | 2 | 3 | 0 |
| 1 | 6 | 7 | −4 |
| 4 | 2 | 6 | −3 |
| 4 | 6 | 10 | −7 |

**Exact set of availability values: {0, −3, −4, −7}.**

Duplicate ways of obtaining a value do not create a different value (R6). Here each of the four values arises via exactly one combination, but the collapse rule would apply if duplicates arose.

Negative availability is permitted (R6) and does not by itself identify a corrupt record or a physical stock discrepancy. Three of the four values are negative; each corresponds to an admissible combination whose summed reservations exceed the capacity of 3.

## Separate bounds (R6, with the RSS projection caveat)

Per-booking lower/upper bound (min/max of possible reservations):

- A: lower 1, upper 4.
- B: lower 2, upper 6.

Sum of lower bounds = 3 → availability **lower bound = 3 − 3 = 0**.
Sum of upper bounds = 10 → availability **upper bound = 3 − 10 = −7**.

**Bounds: [−7, 0].**

The interval [−7, 0] contains −1, −2, −5, −6, which are **not** in the exact set {0, −3, −4, −7}. So on case C the bounds are *not* the set: reporting [−7, 0] as if it were the exact set would admit four availability values that no admissible combination yields. R6 permits reporting the interval as bounds but forbids equating it with the exact set.

Under RSS this is exactly the loss a **projection** incurs when it collapses the per-booking alternative *sets* into min/max scalars before combining. The RSS slogan that a projection is always a loss of information is class-level; on this snapshot the loss is concrete — the interval is strictly wider than the set.

## Whose defect is what (clause vs. application)

- **Language clause:** the WHL specimen's `possible_reservations` and `availability_lower_bound`/`availability_upper_bound` are declared to yield min/max of the alternative quantities and to yield an `Int` interval. That declaration is correct as a *bound* vocabulary and is not defective. Whether it is *sufficient* for the task's R6 requirement of an exact set is a separate question answered below.
- **Application:** the memo's C3 claim that "every projection must lose information" is a misuse of the RSS *class-level* slogan when extended to singleton inputs or to injective projections — on those it is false as a claim about the projection. This is a defect in an application of the slogan, not in the slogan itself, which is stated at class scope. This cycle does not re-litigate C3 here; case C is supplied as fresh use, and the point is noted only where it bears on interpreting [−7, 0] under RSS.

## Remaining problem

One problem remains live and is not resolved by producing correct answers on A and C. The **bounds-versus-set distinction is fragile under repetition**. On case A the endpoints of the interval coincide with the exact set's extremes, so a downstream consumer that reads only [−2, 3] and happens to use its endpoints as the extreme availability values would coincidentally obtain the correct extrema — the coincidence, not correctness, would be doing the work. On case C the interval [−7, 0] is strictly wider than the set {0, −3, −4, −7}, so a consumer reading only bounds would admit four values no admissible combination produces. Nothing in the contract or in RSS supplies a criterion for when the interval and the set coincide, nor a check that a downstream consumer is using the set rather than the interval. This is a limit of the representation in use, not a defect of either snapshot, and I carry it forward rather than resolve it here.
