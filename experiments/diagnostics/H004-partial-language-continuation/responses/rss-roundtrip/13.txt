## 2. Criticism of my cycle-12 response

I proceed in the two registers the block asks for — clause versus application — and add a third, *method*, since the block admits my appraisal practice.

### 2.1 The reflexivity claim is sound and should be retained

Cycle 12's central substantive move — that C3's defect is *partly RSS's own clause*, not C3's alone, so C3 *republicates* an RSS overgeneralization rather than originating it — is correct, and it is confirmed by the specimen text. RSS says, in the Primitives section: "Projection: a function from a viewpoint and a reading to a single answer… A projection is always a loss of information." That universal is RSS's own. On a singleton domain, or on an injective map over the admitted domain, nothing is lost. So the overgeneralization is *at the RSS clause*, and C3's second sentence is a faithful transcription of it. Cycle 12 was right to relocate the primary target from C3 to RSS. I retain this against cycle 11's softer treatment. This does not reject RSS as a class: RSS's slogan is doing rhetorical work — the *paradigm* projection (a single availability number from a set of reservations) *is* lossy — and the corrected scope is "lossy when non-injective over the admitted domain in the way that matters for the question at hand."

### 2.2 Cycle 12 (2.2) claimed to *use* the clause/application distinction; it still did not fully use it, and this is the same defect cycle 12 charged cycle 11

Cycle 12's 2.2 faulted cycle 11 for announcing clause/application separation without carrying it through. But cycle 12's own heading named likely applications — "globalizing a rejection, settling inquiry by one commitment, flattening a set, treating absence-of-algorithm as a decision result, treating predicate-existence as sufficiency" — as descriptions of the *risk types* and did not exhibit any of them against a concrete snapshot or a concrete earlier response. So the identical charge applies to cycle 12: it announced the distinction and again did not display the applications. Concretely, an application-level instance of C1's error would be: taking "account B rejected the task's independence assumption" and concluding that any *booking's* result under account A is false *for the snapshot* — that is an application error about a specific case, distinct from C1's clause-level misreading. Cycle 12 named the type and did not apply it. Amendment to *cycle 12's practice* (not a rewrite of what it said): the applications that exploit C1–C5 should have been run against concrete cases from my own material, not just labeled. I make two explicit now, to close the omission the cycle 12 text left open.

**Application instance of C1.** Suppose account B rejects R5's independence scope (it holds that alternatives across bookings are coupled, not independent). Under C1's step, B's rejection would make my cycle-10 case B conclusion ({5,1}) false *for every account*. That is an application error: B's rejection defeats the *support route* (it disputes the scope assumption, R5) without proving the conclusion false under R5's scope. The case B computation is a conditional claim over a reading; the rejection does not undo the computation; it changes who is entitled to rely on it as an answer for the snapshot. This is exactly what R7 says and what C1's "therefore" forbids.

**Application instance of C5.** The WHL predicate `possible_reservations` exists. Applying it to a snapshot whose relevant record at greatest revision is an *expired hold* yields, from its own `reserves_effect`, quantity 0. That application is *adequate under the WHL reading* — and inadequate as a claim about the warehouse if the governing reading is one in which an expired hold's *expiry deletes it* so a lower revision becomes greatest. The predicate's existence gives no answer to whether that application matched the governing reading. So C5's *application* half fails concretely: existence of the predicate coexists with an open adequacy question about a specific case. This is the instance cycle 12 gestured at without exhibiting, and it belongs to the *application* level rather than the clause tension (e), which is a clause-vs-clause matter.

Consequence: cycle 12's charge against cycle 11 is *correct as a charge* and *self-implicating* — cycle 12 repeated the pattern it criticized. That is a defect in cycle 12's *method*, not a defect in its verdict on cycle 11.

### 2.3 Cycle 12's treatment of C4's residual is correct and should be sharpened only slightly

Cycle 12 (2.4) wrote that C4's residual should be a "stance about forcing a global answer," not an open decidability result. That is right, and it matches the RSS text: RSS "is deliberately noncomputable: it does not provide an algorithm for resolving conflicts, and it treats any demand for a single answer as a projection that must be justified outside the semantics." So the noncomputability *as stated* is a refusal to force a global algorithm. Cycle 12's improvement — from "unresolved scope question" (cycle 11's phrase) to "stance about forcing a global answer" — is correct and should be kept. One further sharpening the sources themselves license: a *projection* is a function of a viewpoint and a reading (RSS's own definition), so a projection is exactly the kind of thing computed once an account and a reading are fixed. C4's inference, "no algorithm in the class ⇒ represented problem noncomputable," thus fails by conflating the *class's* refusal to supply a global algorithm with a *property of a specific function on a specified domain*. Cycle 12 said this; keeping it sharp — the class-noncomputability is a *stance*, not a *theorem about the problem* — is the corrected residual. I retain it as improved over cycle 11.

### 2.4 Cycle 12's (2.5) refinement is correct; the "clause-versus-application" line it drew needs one correction

Cycle 12 (2.5) stated that the `t = expiry` tension (e) is a *clause disagreement* between R4 (`t < expiry`) and WHL's `reserves_effect` (`t ≤ expiry`), not a "clause-right/application-wrong" example, and that my cases A and B do not turn on equality. That is accurate as far as it goes. The correction: cycle 12 wrote it as if the clause/application line had been drawn cleanly there, but the illustration as written faces the *same* application-level possibility I exhibit in 2.2 above — using the WHL function (a clause) in a case where the reading in force says otherwise (an application). The distinction cycle 12 needed to draw explicitly is: (e) is a *clause-vs-clause* disagreement that *underwrites* an *application-level* risk — using one clause where the governing reading supplies another. Cycle 12 mentions the risk; it does not classify it; the correct classification is *clause disagreement feeding an application risk*, not a pure clause case. Correction to cycle 12's framing, preserving what it said.

## 3. Clause-versus-application, summarized

The block's distinction, once applied across C1–C6:

- **Clause defects (memo's description of the representation, or its inferences).** C1 (refutation relation), C2 (commitment locality), C3 (universal loss — shares the defect with RSS's own slogan), C4 (no-algorithm ⇒ noncomputable), C5 (existence ⇒ capture + adequacy). These are defects in the *clauses as stated*, or as inferences from the representation's clauses.
- **Application-level cognates (uses of a clause that go wrong even if the clause is fine).** Using C1's rejection-step to invalidate a case result; using C2's commitment-step to close inquiry for other accounts; using C3's universal to license flattening *any* mapping (including injective ones); using C4's stance-reading to declare a case undecidable; using `possible_reservations` / `reserves_effect` under one reading where another governs. These are separable from the clause defects and each is a *use* error.
- **No defect.** C6; it is the standard that separates clause from application, and it is the reason false-claim-permission is not by itself a defect.
- **Clause-vs-clause disagreement, whose residual feeds an application risk.** (e): R4's `t < expiry` vs WHL's `t ≤ expiry`. Marked as *my* framing category (cycle 7's named form), applied to texts.
