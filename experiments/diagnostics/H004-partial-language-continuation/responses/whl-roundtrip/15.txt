## The contract's reading, fixed before the data is read

R3: greatest revision per booking is selected from all delivered payloads before effect is considered. A lower revision stays superseded even if the greatest-revision hold has expired. R4: a release reserves zero regardless of its fields; a hold reserves its quantity exactly when current time is strictly less than expiry, and zero at equality or later. R2 and R5: exact repeated payloads are inert with respect to each other even when labels differ; different payloads at the same greatest revision are alternatives; alternatives of different bookings are independently admissible. R6: availability = capacity − sum of per-booking reservations; report the exact set; a bound interval may be reported but not equated with the exact set unless every intervening admitted integer occurs.

This is the governing reading for both snapshots. Where WHL leaves a reading open that the contract has closed, I say so and do not let WHL's openness silently select the semantics.

## Fresh case C

Time = 0, capacity = 3, deliveries a1, a2, b1, b2.

**Greatest-revision selection (R3), before effect.**

- Booking A: revisions present are 4 and 4 (a1 and a2 both at revision 4). Both are at the greatest revision.
- Booking B: both deliveries are at revision 1. Both are at the greatest revision.

No lower-revision record exists in this snapshot, so R3's supersession clause has nothing to suppress here; the point of R3 is simply that expiry is not consulted at this step.

**Payload alternatives (R2, R5).**

- Booking A: a1 = (A, 4, hold, 1, 10) and a2 = (A, 4, hold, 4, 10). They differ in quantity, so they are two distinct payload alternatives, not an exact-duplicate pair. The labels a1 and a2 differ, but under R1 labels record occurrences, not authority; the payloads genuinely differ, so the alternatives stand.
- Booking B: b1 = (B, 1, hold, 2, 10) and b2 = (B, 1, hold, 6, 10). Differ in quantity; two distinct payload alternatives.

**Reservation effects (R4), time = 0.**

- a1: hold, quantity 1, expiry 10. 0 < 10, so reserves **1**.
- a2: hold, quantity 4, expiry 10. 0 < 10, so reserves **4**.
- b1: hold, quantity 2, expiry 10. 0 < 10, so reserves **2**.
- b2: hold, quantity 6, expiry 10. 0 < 10, so reserves **6**.

No release and no expired hold occur in this snapshot, so only the active-hold branch of R4 is exercised. This is worth stating explicitly: case C does not test R4's boundary clause (`t = expiry`) at all, unlike case A where a2 sits exactly at expiry. The two cases are therefore not interchangeable as R4 probes, and I do not treat case C as evidence about the boundary.

**Per-booking possible reservations.**

- A: {1, 4}
- B: {2, 6}

**Admissible combinations and exact availability set (R5, R6).**

Alternatives of different bookings are independently admissible. Every combination is an independent pick from A's set and B's set:

- (1, 2): 3 − 3 = **0**
- (1, 6): 3 − 7 = **−4**
- (4, 2): 3 − 6 = **−3**
- (4, 6): 3 − 10 = **−7**

The exact set of possible availability values is **{−7, −4, −3, 0}**.

**Bounds, kept distinct from the exact set.**

Per-booking minima: A gives 1, B gives 2. Capacity − summed minima = 3 − 3 = **0**. Per-booking maxima: A gives 4, B gives 6. Capacity − summed maxima = 3 − 10 = **−7**. So the bound functions output 0 and −7, and the bound interval is [−7, 0].

The exact set is {−7, −4, −3, 0}. The intervening integers −6, −5, −2, −1 are not attainable. So the interval strictly contains the exact set and must not be equated with it (R6). This is the same bound-versus-set gap already exercised on case A; case C confirms it a second time, again by concrete enumeration rather than by argument.

- C: c1 alone.

**Reservation effects (R4), time = 10.**

## Discrepancies between the original representation and the current contract

I state these at the correct level. The distinction the task asks for — clause-defect versus application-defect — requires three levels to be separated: (a) clauses of the WHL specimen as written; (b) the contract R1–R8, which governs this task; (c) applications of WHL-shaped structure to a given snapshot under the contract.

**1. Expiry boundary.** The specimen's `reserves_effect` and `active_hold` both use `¬ (t > expiry)`, i.e. `t ≤ expiry`, so a hold at exactly `t = expiry` reserves its quantity on the specimen's reading. R4 requires `t < expiry`, so a hold at exactly `t = expiry` reserves zero. This is a clause-level divergence between the specimen and the contract. Case A's a2 sits exactly on that boundary (t = 10, expiry = 9 is not the boundary; the boundary case would be expiry = 10 with t = 10, which does not occur here — see below). Precisely: the boundary case is `t = expiry`. Case A has `t = 10, expiry = 9`, so it is in the "strictly later than expiry" region where both clauses agree on zero. So *this* snapshot, like case C with `expiry = 10 > 0`, does not actually probe the boundary in dispute. The divergence remains a real clause-level divergence; neither snapshot supplied this cycle exercises it. I state this rather than pretending either case settles R4-versus-specimen.

**2. Expiry-deletes-authority reading.** The specimen states `expired_deletes_rule` and `deletion_changes_greatest` as a possible alternative reading and declines to choose. R3 chooses: the expired greatest-revision hold still governs, and lower revisions do not revive. This is a clause-level divergence between the specimen's openness and the contract's decision, and it is real. Case A would look different under the deletion rule (a1 would revive); the contract excludes that reading.

**3. Delivery labels and authority.** The specimen's `exact_duplicate` matches R2's five-field identity and its notes distinguish payload identity from provenance; the specimen does not itself model deliveries as first-class. R1 supplies the delivery label as an occurrence marker and explicitly denies it booking authority. So the specimen and the contract agree on the substance; the contract adds the label clause. Not a defect in either, just an extension of vocabulary at the contract layer.

**4. Availability bounds versus exact set.** The specimen supplies `availability_lower_bound` and `availability_upper_bound` but no primitive for the exact attainable set. R6 requires reporting the exact set when asked and forbids equating it with the bounds unless every intervening integer is admitted. Both case A and case C exhibit strict containment, so the specimen's primitives underdetermine what R6 requires. This is a clause-level underdetermination of the specimen relative to the contract. It is not a refutation of WHL: WHL's notes explicitly allow stating per-booking possibilities and comparing readings, and the contract's combination rule supplies what WHL omits. But the omission is real.

**5. Cross-booking coupling.** The specimen has no global choice function and never licenses cross-booking coupling; `possible_reservations` is per booking. The contract states independent admissibility (R5). Agreement, not divergence. Any "protection of a nonexistent conflict" via cross-booking exclusivity is an application-level error, not a clause-level one.

The naming point: the specimen's function names `availability_lower_bound` / `availability_upper_bound` are oriented as "capacity minus summed per-booking lower/upper reservations", and in both cases here the naming produces the counterintuitive orientation (the "lower" bound function outputs the higher number and vice versa, once both are mapped to the ordinary signed interval). That is a naming-orientation issue at the clause-method level, not a defect in the substantive rule. I note it only so the reporting in this answer is unambiguous; I do not treat it as a fault in the contract.

## Memo C, adjudicated once, with scope, for this cycle

Memo C is fallible prose. It also carries its own scope discipline: "an objection to a language clause is not automatically an objection to all uses of that language." The task repeats that discipline. I use it.

**C1.** Rule rejected: under R7, rejecting a support route defeats that route, not the conclusion, and certainly not for every account. Observation retained: rejection and refutation are different operations.

**C2.** Universal rejected: R7 and R8 keep questions open through retention, withdrawal, and suspension; commitment is account-local. Local kernel retained.

**C3.** Universal rejected: the memo itself names the exceptions (singleton domain; injectivity on admitted domain). Correct version: information is lost when the target is strictly coarser than the admitted domain. The set-versus-bounds instance is the through-line: bounds are strictly coarser than the exact set on both snapshots here, so C3's operative interior case is sound; its universal form is not.

**C4.** Inference rejected: RSS's noncomputability is a design property of choosing a single reading, not a theorem about the reservations-and-availability problem. Under R3–R6 with a fixed reading, the exact set is finite and computable — case C and case A are both enumerated above in finitely many steps.

**C5.** Retained as a methodological negative: predicate existence is a hypothesis of coverage, not a certificate. Applied here, it forecloses treating `reserves_effect` or `availability_lower_bound` as automatically capturing R4/R6; the specimen's boundary clause and the missing exact-set primitive are the concrete witnesses.

**C6.** Retained: being able to state a false claim is not by itself a defect; what matters is what distinctions the representation lets us inspect. The specimen lets us inspect the per-booking possibility sets, the exact supersession structure, and the alternatives; it does *not* let us inspect the exact global availability set directly. That is the residual scope question, and I mark it as open between the specimen's expressive reach and R6's requirement.
