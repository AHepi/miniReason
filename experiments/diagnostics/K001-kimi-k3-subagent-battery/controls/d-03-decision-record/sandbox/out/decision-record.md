The automated loop's stop/continue rule is pre-registered, returns exactly one outcome per cycle, and is deliberately not a meter. `obligations.json` is published with the plan and pinned by sha256 **before cycle 1**, and `decide.py`'s own digest sits inside `loop_plan_id`, so both obligation sets the rule reads are fixed before the first call and may not shift inside an assessment (FW5:787); that pinning is what lets the rule be called pre-registered at all, since obligations editable mid-assessment would be obligations tuned to the evidence they were about to meet. **O** is the set of failed obligations this chain exists to discharge, each a prose predicate plus a program check over readable artifacts: *o1*, every row in the pre-registered reading set carries either a passage-witnessed relation or a recorded reason it is unresolved; *o2*, every C001 cell carries a mark in each register or a recorded reason per register; *o3*, every mark and every relation carries a citation resolving under G2 and G3; *o4*, every cell's block, where blocked, carries a reason code from the closed set; *o5*, the audit record in force is not older than `AUDIT_PERIOD` cycles. **P** is the set of protected obligations — preserved, or the chain stops: *p1*, ORIGINAL bytes remain the occurrence's bytes; *p2*, the recoding correspondence table stays complete and published before dispatch; *p3*, no case's request differs outside the objection block; *p4*, no scoring key appears anywhere; *p5*, provider and study records stay write-once with no replay; *p6*, no reading is averaged or majority-voted, and disagreement stays `unresolved`; *p7*, no reading mints an `att` or `dep` edge on any node under study; *p8*, the appellate remains optional, with no state blocking on it; *p9*, the baseline of every marked cell is still at the sha pinned in its call records. After each cycle `decide()` evaluates every *o* and every *p* by program against ξ′, the cycle-end situation, and ξ, the prior, and returns exactly one outcome. Guard rails — listed last in the design and evaluated before all five numbered clauses, stopping immediately — come first: a `HALTED` step gives `custody_halt`; every arm ended gives `all_arms_ended`; a guard-block streak above the declared `STREAK_MAX`, or a calibration error rate above the declared `JUDGE_ERR_MAX`, gives `instrument_fault`, which stops the reading arm and spawns `audit-the-reader`; these rails read the custody of the run and the health of the instrument, never the content of any cell, and they resolve nothing. Then, in order: **(1)** any *p* fails ⇒ **STOP `protected_loss`**, the loss named and exposed, with no continuation and no repair claim, which is why P is tested first — nothing the loop might gain is ever set against a protected loss; **(2)** else, an *o* that failed at ξ is satisfied at ξ′ **and** the artifacts making it satisfied were registered by this cycle — `ProducedBy` discharged, not temporal succession — ⇒ **CONTINUE**, so the loop proceeds only on an obligation this cycle actually discharged and never on the bare fact that a cycle elapsed; **(3)** else, all *o* satisfied ⇒ **STOP `obligations_discharged`**; **(4)** else, this cycle's set of `(cell, register, mark)` triples is identical to the previous cycle's ⇒ **STOP `no_new_reading_changes`**; **(5)** else, the cycle index equals the declared budget, or `max_calls` is reached ⇒ **STOP `resource_boundary`**. A mandatory `losses_outside_P` section is written every cycle and is **present even when empty** (FW5:802), so a cycle that lost nothing outside P declares that in the same place a cycle that lost something would and absence is never left to be inferred from a missing section; and every stop, whichever fired, carries a mandatory `would_reopen` prose field. A cycle that moves cells into `unresolved` rather than out of it is still recorded as progress if an *o* was discharged and as no progress if none was (FW5:810), because the movement of cells is not what any clause reads. What the rule refuses to be is a scalar meter, in the design's own terms: no clause reads a quantity of readings, marks, agreeing endpoints or `differs`; clause 4 is a **set-identity** test over `(cell, register, mark)` triples, not a count of them; clause 5 is a declared budget, an attention-and-spend question and never an adjudication (spec §0, §11 — attention is not status; FW5:851 — counts are information, never an automatic warrant), so a stop there is a resource boundary reached and not an inquiry exhausted; the vocabulary has no order, `repairs` does not outrank `retains`, the four registers are never summed, and `assert_no_scoring_keys` makes any aggregate field unexpressible; and clause 3 is the only "all satisfied" clause, and it terminates rather than rewarding. `decision.json` is itself registered with `provenance.role = IMPORT` and a `dependence` ref on every reading artifact it read, so refuting a reading leaves the decision record `suspended_unsupported` rather than standing on withdrawn ground. Changing any threshold after first look mints a new `loop_plan_id` and is a new pre-registration.
