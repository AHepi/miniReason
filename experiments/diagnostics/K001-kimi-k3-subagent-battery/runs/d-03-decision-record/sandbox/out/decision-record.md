The automated loop's stop/continue rule is pre-registered and frozen before it is allowed to run: O and P, the two obligation sets the rule reads, are published in `obligations.json` alongside the plan and pinned by sha256 before cycle 1, they may not shift inside an assessment (FW5:787), and `decide.py`'s own digest is folded into `loop_plan_id`, so the obligations and the code that judges them are pinned together. O is the set of failed obligations this chain exists to discharge, each one a prose predicate plus a program check over readable artifacts; P is the set of protected obligations, each of which is preserved intact or the chain stops. After each cycle, `decide()` evaluates every o and every p by program against ξ′, the cycle-end situation, and ξ, the situation before it, and returns exactly one outcome. Guard rails are evaluated before any outcome clause and stop immediately when they fire: a `HALTED` step stops the loop on `custody_halt`; every arm having ended stops it on `all_arms_ended`; and a guard-block streak above the pre-registered `STREAK_MAX`, or a calibration error rate above `JUDGE_ERR_MAX`, stops it on `instrument_fault`, which halts the reading arm and spawns `audit-the-reader`. The outcome clauses then apply in a fixed order, each reached only if none above it fired: if any p has failed, the loop stops on `protected_loss`, the loss named and exposed, with no continuation and no repair claim; otherwise, if an o that failed at ξ is satisfied at ξ′ and the artifacts that made it satisfied were registered by this cycle — `ProducedBy` discharged, provenance and not temporal succession — the loop continues; otherwise, if every o is satisfied, it stops on `obligations_discharged`; otherwise, if this cycle's set of `(cell, register, mark)` triples is identical to the previous cycle's set — a set-identity test, not a census — it stops on `no_new_reading_changes`; otherwise, if the cycle index equals the declared budget or `max_calls` is reached, it stops on `resource_boundary`, a declared attention-and-spend boundary and never an exhaustion of the inquiry. Every cycle also writes a mandatory `losses_outside_P` section, present even when it is empty (FW5:802), and every stop carries a mandatory `would_reopen` prose field, so no ending performs a finality it has not earned. This is not a scalar meter, in the design's own terms: no clause reads a quantity of readings, marks, agreeing endpoints or `differs`; clause 4 is a set-identity test over those triples, not a count of them; clause 5 is a budget declared in the pre-registration, an attention-and-spend question, never an adjudication (spec §0 and §11 — attention is not status; FW5:851 — counts are information, never an automatic warrant); the vocabulary has no order, `repairs` does not outrank `retains`, the registers are never summed, and `assert_no_scoring_keys` makes any aggregate field unexpressible; and the all-satisfied clause, the only one that could be mistaken for a reward, terminates the loop instead. What the rule refuses to be is a measure of progress, a ranking of readings, or a conversion of volume into warrant — and it refuses quiet amendment: changing any threshold after first look mints a new `loop_plan_id` and is a new pre-registration, never an edit to this one.
