## Blockers

### B1 — the history-rewrite guard passes eight destructive argvs
`publish.py:164-177` (`REWRITING_SUBCOMMANDS`, `REWRITING_FLAGS`), `:310-322` (`_refuse_history_rewrite`).
**Claim.** Module docstring `publish.py:73-77`: "Never: … or any other history-rewriting git invocation. `_refuse_history_rewrite` inspects the argv before a process is spawned, so the refusal holds for **every caller of `LocalGit`**." `HistoryRewriteRefused` docstring `:223-224`: "An argv that would rewrite, discard or delete recorded history." §8 pre-registration (`receipts.py:707-708`) lists history rewrite as not authorised.
**Evidence.** Executed `_refuse_history_rewrite` over a probe table; ALLOWED: `push -d origin claude/x` (deletes the remote branch — `-d` is the short form of the listed `--delete`), `push --mirror`, `push --prune …`, `update-ref -d refs/heads/x`, `update-ref refs/heads/x 000…0`, `branch -D x`, `stash push`, `checkout --orphan`, `symbolic-ref HEAD …`. Refused correctly: `--amend`, `--force`, `+src:dst`, `rebase`, `reset --hard`, `worktree --force`. `publish()` itself never emits these — but `LocalGit` is the published seam every later wave uses, and its docstring is the reason a W1 author will not add a second guard.
**Fix.** Invert to an allow-list of the subcommands this module needs (`add commit push ls-files ls-remote fetch rev-parse show diff merge-base status`) and refuse everything else; separately add `-d`, `-D`, `--mirror`, `--prune`, `--prune-tags` to `REWRITING_FLAGS`. A deny-list's failure mode is the entry nobody thought of.
**Test.** `test_publish.py`: a table of ≥12 destructive argvs, each asserted to raise `HistoryRewriteRefused`, `push -d` and `update-ref -d` named explicitly; plus an assertion that every argv `publish/verify_published/check_published` actually emit is on the allow-list.

### B2 — G12 silently passes a rendered file and a table header
`contracts.py:618-633` `assert_no_scoring_keys`; the same shape at `standard.py:187-196`.
**Claim.** Design §2.4 G12: run "over every emitted artifact, **every table header and every rendered file**". §5 P4: "no scoring key appears anywhere" is a *protected* obligation whose failure is `STOP protected_loss`.
**Evidence.** Executed: `assert_no_scoring_keys("| cell | relation | score | rank |")` → `None`. `assert_no_scoring_keys("READING_TABLE.md\n\n| best endpoint | merit |\n…")` → `None`. Also silent on a `set`, and on a `CriticOutput` dataclass. Only a `Mapping`/`list`/`tuple` is inspected. So P4 is unfalsifiable on two of its three named subjects: a published `READING_TABLE.md` with a `score` column passes, and `decide()` reports P4 satisfied.
**Fix.** Make the function raise `ContractError` when handed `str`/`bytes` (a rendered file is not a key structure and must not silently pass), and add a companion `assert_no_scoring_headers(text)` that tokenises Markdown table headers and Markdown headings against `FORBIDDEN_KEYS`. Both belong in wave 0 because W3-REPORT is the caller.
**Test.** `assert_no_scoring_keys("| score |")` must not return `None`; `assert_no_scoring_headers` refuses a header row containing each member of `FORBIDDEN_KEYS` and admits the frozen ceiling text unchanged.

### B3 — a config can turn off a pre-registered guard the standard says is on
`types.py:607-637` (`SeatsConfig`: `paraphrase_n` low=**0**, `schema_repair_budget` 0..1, `min_judge_families` 2..8, all with defaults), `types.py:829` (`reopen_reasons=_unique_texts(...)`, unconstrained) vs `standard.py:694-736`.
**Claim.** `AuditConfig` docstring `types.py:681-683`: "a threshold that appears by default was never pre-registered." §2.4 G11: the reopen-reason list is "the only mechanical defence against retrying until something sticks". §2.1: the guard parameters are frozen in the standard.
**Evidence.** Executed: `LoopConfig.from_mapping` accepted `seats.paraphrase_n = 0` (G7 off) and `schema_repair_budget = 1` while `standard.GUARD_PARAMETERS` says 2 and 0 — and `build_standard(params={... paraphrase_n: 0 ...})` *refuses* with `GUARD_PARAMETER_INVALID`, so the two owners have disjoint admissible ranges. It also accepted `reopen_reasons = ["because-i-said-so", "try-again"]`. Nothing in wave 0 compares `config.seats.*`/`config.reopen_reasons` with the standard's; both are inside `loop_plan_id`, so the disagreement is frozen rather than caught, and W1/W2 must guess which owner wins.
**Fix.** One reconciliation function in `standard` (which may import neither `types` nor be imported by it — so put it in `standard` taking a plain mapping): `assert_config_matches_standard(seats_mapping, reopen_reasons)`, raising `GUARD_PARAMETER_INVALID` / `REOPEN_REASON_UNKNOWN`; call it from PREFLIGHT. Align `SeatsConfig`'s ranges with `_INT_PARAMS` (`paraphrase_n` low=1) in the same commit.
**Test.** For each of `paraphrase_n`, `schema_repair_budget`, `min_judge_families`, a config value differing from `GUARD_PARAMETERS` is refused; `reopen_reasons` outside `standard.REOPEN_REASONS` is refused; the module default config reconciles.

## Should-fix

**S2 — the ledger default silently creates a second ledger, and letter minting is only collision-free per file.** `receipts.py:126-129` `DEFAULT_REPO_ROOT = parents[3]`; `_append`/`_open_append` `:366-456`. Executed: `open_receipt(..., ledger_path=<nonexistent file in a temp dir>)` created the file and minted `REC-20260914-A`. In a wheel `parents[3]` is not the repo, so the default writes a new ledger (or raises a bare `FileNotFoundError` if `docs/` is absent) and two agents both mint `-A`. O3 records this as a convention ("always pass `ledger_path=`"), which is not a mechanism. **Fix:** `_append` refuses a ledger that does not exist unless `create=True` is passed explicitly (`LEDGER_NOT_FOUND`, added to `FAILURE_CODES`); resolve `DEFAULT_REPO_ROOT` by walking up for `tools/repo_activity.py` and set the default to `None` when not found. **Test:** appending to a missing ledger without `create=True` raises; the existing `test_appending_to_a_missing_ledger_creates_it…` becomes the `create=True` case.

**S1 — a CRLF checkout silently changes `loop_plan_id`.** `standard.py:236-237`, no `.gitattributes` anywhere in the tree. Executed against a CRLF copy of `data/*`: `CEILING_SHA256` `1e26be…` → `61507d…` and `STANDARD_BODY_SHA256` `a2d944…` → `e3915a…`, with 11 required sentences still parsing (text-mode universal newlines hide it) and every test still green. `custody.sha256_path` reads bytes, so the pin diverges too. `docs/lessons/operations.md:62` (OPS-20260914-LEDGERCRLF) already states the rule: "the scope is any tracked file whose bytes are evidence." **Fix:** ship `.gitattributes` with `* text=auto eol=lf` plus `src/minireason/loop/data/** -text` and `docs/DECISION_LEDGER.md -text`. **Test:** `assert b"\r" not in CEILING_PATH.read_bytes()` and the same for the mirror; assert `CEILING_SHA256 == "1e26be…"` as a literal.

**S4 — the §2.3 contracts are not in any pinned artifact.** `types.py:183-190` `PINNED_SOURCE_PATHS` names six repo files and no module of `minireason/loop`. `contracts.WORD_LIMITS` and the five role schemas are pre-registered guard content (§2.3), yet editing them changes no digest: `loop_plan_id` folds `config ∪ pins`, and the standard body (which *is* pinned) does not carry them. §5: "Changing any threshold after first look mints a new `loop_plan_id`." **Fix:** add `{"contracts_sha256": sha256(canonical(SCHEMAS)), "word_limits": dict(WORD_LIMITS)}` to the standard body under a new section (a successor standard, so a new digest by construction), or add the six loop modules to `PINNED_SOURCE_PATHS`. **Test:** mutate one `WORD_LIMITS` entry in a copy and assert the plan id changes; today it does not.

**S5 — the exhaustion exemption is byte-exact and case-sensitive, and refuses the ceiling it exists to protect.** `standard.py:258-284`. Executed: the frozen text passes, but `"…boundary, Not exhaustion of the inquiry."` (sentence-initial), `"NOT EXHAUSTION OF THE INQUIRY"` (a caps heading) and `"not exhaustion of the\ninquiry"` (a re-wrap) are all refused with `RESOURCE_BOUNDARY_MISDESCRIBED`. That directly contradicts deviation 3 (`standard.py:56-57`), which stores the clauses unwrapped "so that 'appears verbatim' survives a renderer that re-wraps". W3-REPORT will hit this. **Fix:** normalise whitespace and case in the scanned copy before removing the denial (`re.sub(r"\s+"," ",text).casefold()` vs the denial casefolded). The smuggle direction is already safe — see below. **Test:** the denial in sentence case, upper case and re-wrapped all pass; `"the reading was exhaustive"` still refused.

**S6 — the audit thresholds are bare constants whose margin carries no account.** `types.py:677-702` `AuditConfig(period, judge_err_max, streak_max)`. `docs/reviews/fw5-vs-harness-spec-2026-09-14.md:190` charges the spec with exactly this shape: "`HV_MIN` is a bare config constant whose margin carries no account". FW5:814 excludes "an endorsement count or an ungrounded satisfaction report" from an epistemic obligation; R9 requires a stated anchor. The ceiling and §8 name `JUDGE_ERR_MAX`/`STREAK_MAX` but neither a value nor a reason. **Fix:** make `AuditConfig` require a sibling account string per threshold (`judge_err_max_account`, `streak_max_account`, non-empty), so the margin is inside `loop_plan_id` and is attackable. **Test:** a config whose audit block omits an account is refused with `CONFIG_MISSING_KEY`; the account text appears in the rendered audit record.

**S10 — nothing stops a later wave computing the calibration rate per seat, which is ranking endpoints.** `types.py:687` + design §2.5. The anchors are run per seat, so `errors/anchors` is naturally per seat; comparing two seats' rates is a merit predicate over endpoints (FW5:849, ceiling clause 8: "Endpoints are independent occasions … never competitors"). §2.5's per-hit demonstrative warrant is the FW5-clean mechanism; the rate is not. **Fix:** state in `AuditConfig`'s docstring that the rate is a panel-level instrument signal, never computed per seat for comparison, and that `instrument_fault` names the instrument and not a losing seat. **Test:** `assert_no_scoring_keys` over the rendered audit record; an oracle asserting the audit record carries no per-seat numeric field and no two-seat comparison.

**S7 — `judge_seats` may be raised to 8 while the frozen unanimity text says "Both".** `standard.py:700-704` `_UNANIMITY_RULE` vs `:730` `judge_seats:(2,8)`. Executed: `build_standard(params={... "judge_seats": 8 ...})` succeeds and ships a rule reading "**Both** judge seats must return the same `sustained` value." A successor standard with three seats therefore ships a rule describing two, and the natural repair is a majority — the one thing G5 forbids. **Fix:** generalise to "*every* judge seat must return the same `sustained` value", or clamp `judge_seats` to exactly 2 in `_INT_PARAMS` and make a wider panel a successor standard's problem. **Test:** for each admissible `judge_seats`, the rendered `unanimity_rule` contains no numeral or "both", and contains "every".

**S8 — the code-table scan is blind to keywords, name indirection and f-strings.** `tests/loop/test_types.py:303-337`. Executed against a sample: `LoopError(code="UNDECLARED_KEYWORD_CODE")`, `_fail(code="X", detail=…)`, `CODE = "Y"; LoopError(CODE)` and an f-string all yield the empty set. It also globs `PACKAGE.glob("*.py")` only (a later wave's subpackage is unscanned), and checks one direction only — 11 of `SCHEMA_REASONS`' 18 members are never seen because 7 live in the `_JSONSCHEMA_REASONS` dict literal, and no test asserts a table member is reachable. **Fix:** read `ast.Call.keywords` as well as `args`; resolve module-level `NAME = "LITERAL"` constants; glob `rglob("*.py")`; add a reverse assertion listing unreachable table members as an explicit allow-list. **Test:** the scan finds a token passed by keyword; an unreachable `FAILURE_CODES` member fails unless allow-listed.

**S9 — cross-process *minting* is untested.** `tests/loop/test_receipts.py:205-237` mints from 8 threads in one process, where `_APPEND_LOCK` (an `RLock`) already serialises everything; `:239` runs two processes but only through `ledger_append`, which mints nothing. The load-bearing claim (`receipts.py:22-25`) is about two processes. I ran three processes × 12 `open_receipt` calls against one ledger: 36 ids, 36 unique, 36 paragraphs — it holds, but nothing in the suite pins it. **Fix:** none needed. **Test:** promote my probe — three `subprocess` workers minting under a barrier, asserting unique ids and one paragraph each.

**S3 — a timed-out activity logger escapes the code table.** `receipts.py:834-836`. Executed: a runner raising `subprocess.TimeoutExpired` propagates it unchanged; it is not a `LoopError`, so `except LoopError` misses it and the step cannot name a `failure_code`. `getattr(result, "returncode", 0)` also lets a runner with no `returncode` pass silently. **Fix:** wrap the call, raising `ReceiptError("ACTIVITY_LOGGER_FAILED", "timed out")`; require `returncode` rather than defaulting it. **Test:** a runner raising `TimeoutExpired` raises `ACTIVITY_LOGGER_FAILED`.

**S11 — `VALIDATORS` cannot pass `register`.** `contracts.py:856-858` binds `lambda raw, _role=role: check(_role, raw)`, so every marker validated through `VALIDATORS` gets the seven-token union rather than its register's own (O11). **Fix:** `lambda raw, *, register=None, _role=role: check(_role, raw, register=register)`. **Test:** `VALIDATORS["marker"](body, register="G")` refuses a `T` token.

## Notes

**N1.** Ceiling clause 7 (`data/ceiling_v1.md:13`) promises block counts on every table but states no denominator and no anchor (R9); a renderer must print per-code counts and never a computed rate. Worth a W3 test: the block register contains no `/`, `%` or float.
**N2.** `custody.write_new` (`custody.py:386-393`) fsyncs the file but not the parent directory, so the docstring's "a receipt that resolves a spent call must survive the process" does not hold across power loss for the *name*.
**N3.** Importing `receipts` or `publish` loads all 24 endpoints from disk at import (`receipts.py:82`, `publish.py:91`), which `custody.py:275-287` deliberately avoids "so that importing custody never drags the transport … in as a side effect". Two of six modules do it anyway.
**N4.** `verify_published(repo, paths, commit)` (`publish.py:741-768`) also byte-compares the *working tree* (`_read_back:642`), so it answers `False` for a genuinely published commit once the tree moves on.
**N5.** One publish step can burn 5×90 s of git timeout plus 30 s of backoff (`publish.py:154`, `:610-618`), exceeding the 300 s cadence deadline by construction.
**N6.** `contracts._critic_failure:737` lets a critic return both a named relation and a non-empty `outside_vocabulary`; `CriticOutput.relation` still names the relation while `claims_relation` is `False`. A renderer reading `.relation` prints a relation for a cell that must read `unresolved`.
**N7.** No test asserts the two data files ship in a built distribution — `test_standard.py:208` checks the source tree only. I could not build a wheel here (installed setuptools 68.1.2 against the declared `>=75`; the build fails on Debian's `install_layout`), so the `package-data` entry is unverified.
**N8.** `judge_err_max` is a fraction over a 5-anchor set, so its attainable granularity is 0.2: any threshold below 0.2 means "one wrong anchor ends the reading arm". Say so where the threshold is declared.
**N9.** Design §4.4 promises "a test asserts [the token *exhaustion*] never appears in a generated record". The wave-0 tests assert it of the vocabularies and of `types.py`'s source; nothing calls `assert_no_exhaustion_claim` on a generated record, because wave 0 generates none. Carry it as a W3 obligation.

## Tried, and could not break

* **Smuggling the token past `assert_no_exhaustion_claim` by embedding the denial.** `"The inquiry is exhaust" + DENIAL + "ed."` — removal concatenates the halves into `exhausted`, which the stem scan then catches. Overlapping denials, doubled denials and a denial split across the claim all fail the same way. The scan is over-strict (S5), never under-strict.
* **Cross-process receipt-id collision.** Three processes × 12 `open_receipt` against one ledger: 36 unique ids, each appearing exactly once. Mint and append genuinely share one `flock`, and the pre-existing bytes were untouched.
* **CRLF ledger corruption.** Appending to a `\r\n`-terminated ledger yields `\r\n` + `\n` + text + `\n`; `_separator` (`receipts.py:407-420`) inspects both forms and only ever adds.
* **Forcing a push through `ref` spelling.** `split_publish_ref`'s `_REMOTE_RE`/`_BRANCH_RE` admit neither `+` nor `:`, so no `ref` can become a force refspec, and `--force`/`--amend`/`+src:dst` are all refused. The hole is elsewhere (B1).
* **Escaping the fence.** `fenced()` refuses `..` before resolution and resolves the final component, so a symlink at the target or at a parent that points outside the root is refused.
* **Digest identity.** `custody.digest(v) == sha256_hex(canonical_json(v))` exactly — `deepreason_core.canonical.canonical_json` is the same `sort_keys/compact/ensure_ascii=False` call with the same default `.encode()`. `encoded` is a genuinely different encoding that round-trips to the same digest.
* **The metric-creep oracle itself.** `test_standard.py:422` (every integer in the pinned body lies under `guard_parameters.`, and there are no floats at all) holds, and is the strongest form of ruling 7's check available at this layer.
